## 0. 넘겨받기 (10초)
(기백) "…이제 실물로 보여 드리겠습니다."

"시연은 제가 맡겠습니다."

## 1부. 차가 스스로 판단합니다 (약 1분 30초)

**① 구성 소개**
[노트북 → Pi → 보드 순서로 가리킴]
"노트북이 서버와 이용자 앱 역할을 합니다. 이 라즈베리파이는 Wi-Fi로 받은 요청을 USB로 보드에 넘겨 주는 중계만 하고요. 이 STM32 보드가 차에 달리는 모듈이고, **허용할지 말지 최종 판단은 이 보드가 합니다.**"

**② 키 등록**
[웹: 공유 키 만들기 → 차에 키 등록]
"주인이 공유 키를 만들어서 차에 등록했습니다."
▶ OLED `KEY OK` / `KEY 8`

**③ 문 열기**
[스위치 누른 채로 웹: 문 열기]
"이용자가 문 열기를 누르면, 보드가 키를 직접 검증하고 잠금을 풉니다."
▶ 서보 열림, OLED `ALLOW` / `LEFT 3` / `UNLOCK EST`

**④ 다시 잠그기**
[스위치 뗌 → 다시 눌러 2초 유지]
"문을 열었다가(▶ `DOOR OP`) 닫으면(▶ `DOOR CL`) 자동으로 다시 잠급니다. 이 버튼은 문 닫힘 센서 대신이고, 문짝을 달면 닫힐 때 눌리게 할 예정입니다."
▶ 서보 잠김, `LOCK EST`

## 2부. 취소했는데 차가 오프라인이라면 (약 2분 30초)

**⑤ 차량 오프라인**
[2초 이상 기다린 뒤 웹: 차량 오프라인 → 5초 기다림]
"이제 지하 주차장처럼 차가 서버와 연결이 끊긴 상황을 만들겠습니다. 실제로는 서버의 동기화 응답만 끊은 거고, 앱과 차 사이는 그대로입니다."

**⑥ 키 취소**
[웹: 공유 키 취소]
"주인이 키를 취소했습니다. 하지만 차는 오프라인이라 **이 사실을 알 수 없습니다.** 이건 구조적인 한계라서 저희도 없앴다고 말하지 않습니다."
▶ 웹 "차는 아직 모름"

**⑦ 문 열기 4번**
[웹: 문 열기 → 스위치 뗌 → 2초 누름] × 4
"차는 취소를 모르니까 열어 줍니다. 대신 공유할 때 정해 둔 오프라인 횟수, 4회까지만 열립니다."
▶ `LEFT 3 → 2 → 1 → 0`, 매번 서보 열림 → 잠김

**⑧ 문 열기 2번 더**
[웹: 문 열기] × 2
"횟수를 다 쓰면 05로 막힙니다. **취소를 알아내서 막은 게 아니라, 정해 둔 한도가 끝나서 막힌 겁니다.**"
▶ `DENY 05`, 서보 안 움직임

**⑨ 차량 온라인**
[웹: 차량 온라인 → 5초 기다림 → 문 열기]
"연결이 돌아오면 차가 인증된 동기화로 취소 사실을 받아서, 이제는 03, 취소된 키로 거부합니다."
▶ `DENY 03`

## 3. 마무리 (30초)
"정리하면, 같은 상황에서 서버 취소만 하는 방식(A)은 6번 다 열렸고, 오프라인 횟수 제한 방식(C)은 4번 열렸습니다. 11/2와 오늘 실물로 **각 1회** 확인한 결과입니다.
C는 저희가 만든 방식이 아니라 비교 대상 중 하나입니다. 저희 목표는 이런 제한 방식들을 **실제 보드에서 같은 조건으로 비교해서**, 차를 공유할 때 어떤 방식을 고를지 판단할 근거를 만드는 것입니다."

**한계 (먼저 말하기)**
"아직 한계도 있습니다. 키 기록이 RAM에만 있어서 **재부팅하고 다시 등록하면 횟수가 다시 4가 됩니다.** 그래서 지금은 재부팅 한 번당 상한입니다. 11/16에 내부 플래시 저장을 넣고 이 부분을 시험할 예정입니다."

## (선택) 보안 — 시간이 남거나 질문이 나오면 (20초)
[웹: 위조된 요청 → 가로챈 요청 다시 보내기]
"키 없이 만든 요청은 인증값이 안 맞아서 01, 예전 요청을 녹음했다가 다시 보내면 일회용 숫자가 달라서 02로 거부합니다."
▶ `DENY 01`, `DENY 02`, 서보 안 움직임

## 예상 질문
| 질문 | 답 |
|---|---|
| Pi가 해킹되면? | "Pi는 줄을 넘겨 주기만 합니다. 키 검증(HMAC)과 남은 횟수는 STM32가 판단해서 Pi로는 제한을 풀 수 없습니다." |
| 온라인인데 왜 `LEFT 3`에 머물러요? | "매번 1회씩 깎고, 서버가 인증된 동기화로 확인해 줄 때만 다시 채웁니다. 온라인에서는 2초마다 채워지고, 끊기면 4회 뒤 막힙니다." |
| 정상 이용자도 막히지 않나요? | "맞습니다. C는 취소 안 된 이용자도 오프라인에서 4회 뒤 막힙니다. 그게 제한의 비용이고, 방식별로 비교할 평가 축입니다. 아직 측정 전입니다." |
| 몇 번 시험했어요? | "실물로 각 1회입니다. 반복 시험(T01~T08)은 아직 목표입니다." |
| 시간 제한(기간)은? | "기간 방식(B·D)은 코드는 있고, 보드 시계(RTC)를 붙인 뒤 11/16 이후 시험합니다." |

## 문제 생기면
| 증상 | 할 말 / 할 것 |
|---|---|
| OLED 멈춤 | "화면 연결이 잠깐 끊겼습니다." → **5~10초 대기 → RESET → OLED 전원 뺐다 꽂기**. 몇 번째에서 풀렸는지 기억. RESET했으면 키 다시 등록 |
| `FAULT` | "잠그는 중 문이 열려 안전 오류로 멈춘 겁니다." → RESET → 키 다시 등록 → 이어서 |
| 서보 안 움직임 | 배터리 연결 확인 |
| 탭 B `ONLINE` 아님 | 중계 다시 실행 → RESET → 키 다시 등록 |
