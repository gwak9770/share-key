## 5. 시험 결과
모두 **1회 시행**. 서보·배터리는 연결하지 않았다. T01~T07 목표 달성으로 쓰지 않는다.

| 시험 | 방법 | 결과 (캡처) |
|---|---|---|
| v2 zip 검토 | 압축 해제 후 파일 목록·문서·해시 확인 | 51개 파일. `sharekey.c` 등 4개 sha256 = manifest. `config.h` 기본: C, SERVO=1, MOTOR=0, ENDPOINTS=0, TEST=0, RTC·OLED·반납버튼·IWDG 끔 |
| CubeMX 설정 | GPIO Settings, Advanced Settings 화면 | PD14 = TIM4_CH3 (Alternate Function), `MX_TIM4_Init` 호출 안 함 |
| main.c | 생성된 코드 확인 | `MX_GPIO_Init`·`MX_USART3_UART_Init`·`MX_RNG_Init`만 호출, `sk_app_run()` 유지 |
| 빌드 | Clean(복사본만) → Build | **0 errors, 1 warning** (`'MX_TIM4_Init' defined but not used`, main.c 191행 — 의도한 것) |
| 업로드 | Run As, 설정 Project = `sharekey_f429_v2` | `sharekey_f429_v2 [STM32 C/C++ Application]`, Download verified |
| 부팅 | miniterm COM4, RESET | `# boot F429 vehicle control v2`, `# MODE=C ENDPOINTS=0 SERVO=1 MOTOR=0 TEST=0`, 2초마다 SYNCREQ, OFFLINE |
| 판단 연동 (C) | server.py + `pi_relay.py --serial COM4` + app.py | 아래 표 |

| 요청 | 앱 결과 | 보드 로그 (중계 창) |
|---|---|---|
| 동기화 | — | `server sync ok -> ONLINE`, `SYNC applied ver 0 -> 1` |
| register 7 | 등록 성공 | `KEY ok kid=00000007 limit=4` |
| open 7 (온라인) | 허용, 남은 3 | `AUTH ALLOW CMD=01 LEFT=3 ACT=OK` → 약 1초 뒤 `ACT DONE POSITION=UNLOCKED SOURCE=ESTIMATED` |
| tamper 7 / replay 7 | 거부 01 / 02 | `DENY ... reason=01` / `reason=02`, ACT 줄 없음 |
| net off → revoke 7 → open 7 ×6 | 1~4회 허용(3→2→1→0), 5·6회 거부 **05** | 허용 4회 모두 `ACT=OK`·`ACT DONE`, 거부 2회 `reason=05`·ACT 없음 |
| net on → open 7 | 거부 **03** | `SYNC applied ver 1 -> 2`, `ONLINE`, `reason=03` |

- **취소 후 추가 사용 C 4/6** — v2 적용 전(10/28) 결과와 같음
- 허용 때만 서보 명령이 나가고 거부 때는 나가지 않음(로그 기준)
- `LINK_STALE` 없음 → 노트북 중계의 HB 정상
- `SOURCE=ESTIMATED`는 끝점 센서가 꺼져 있어 **시간(500ms)으로 추정**한 위치다. 서보가 실제로 움직였다는 뜻이 아니다
- 시험 중 실수: 처음에 `net off`와 `revoke 7`이 한 줄로 붙어 오류(`unrecognized arguments`) → 둘 다 실행 안 됨. 그 사이 open 6회는 온라인 상태라 모두 허용(동기화로 횟수 복구, 정상 동작). 오프라인 부분만 다시 해서 위 결과를 얻음
- 확인 못 한 것: 서보 실물 동작, Pi 5 경유 v2, A 방식 v2 빌드, 모터·센서·OLED·RTC, 재부팅 후 상태(저장 미구현)

## 8. 참고 (사용한 자료, AI 대화에서 나온 중요한 내용)
- 곽동규_작업총정리_F429제어_Pi연동_20261030.md, `stm32_vehicle_control_f429_v2.zip`의 `docs/INTEGRATE_CUBEIDE_KO.md`, `examples/servo_test_f429/README_KO.md`, `vendor/sharekey/SOURCE_MANIFEST.json`
- 진행률(추정, 측정값 아님): 프로젝트 전체 약 30%, 중간발표 준비 기준 약 80% — 00 §10·§11 기준으로 나눠 본 값
- v2 적용 요점 (CubeIDE 수동)
  1. 원본 프로젝트 Ctrl+C/V로 복사 → `.ioc` 이름 변경 → 복사본 안 원본용 `.launch` 삭제
  2. v2 `Core/Inc`·`Core/Src` 끌어다 놓기 → Copy files → Overwrite All
  3. PD14 클릭 → TIM4_CH3 → TIM4 Channel3 = PWM Generation CH3 → GPIO Settings에서 **PD14** 확인(PB8이면 안 됨)
  4. Project Manager → Advanced Settings → `MX_TIM4_Init` "Do Not Generate Function Call" 체크 → Ctrl+S → Generate
  5. Clean은 "Clean all projects" 해제 후 복사본만 → Build → **Run As**(Project 이름 확인)
- 명령은 한 줄씩 Enter. 두 명령을 한 번에 붙여 넣으면 한 줄로 합쳐져 실행 안 될 수 있음
- 비밀번호·Wi-Fi 정보는 기록하지 않음
