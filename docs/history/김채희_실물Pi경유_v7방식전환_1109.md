## 1. 한 일 (요약 3줄 이내)
- Pi에 1106c `pi_relay.py`를 복사하고 **실물 Pi 경유**로 `_v6`를 연결했다(`문 상태 알림 port=9101`, `DOOR STATE OPEN`, `ONLINE`). 이번에도 처음엔 `--server`에 Pi IP를 넣어 OFFLINE이 났다.
- 중간발표 PPT(1107)·대본을 00 v0.3.11과 기록에 맞춰 확인하고, 부스 반복 시연의 **키 한도 위험**(보드 키 8개·동기화 목록 16개)을 코드에서 찾았다. 발표장 세팅 순서 MD를 만들었다.
- `VC_DEMO_MODE_SELECT 1`로 **`_v7`**을 만들어 올렸고, USER 누른 채 RESET으로 **A 방식(`LEFT INF`)**이 뜨는 것을 봤다. 발표에서는 쓰지 않고 C만 하기로 했다.

## 5. 시험 결과
모두 **1회 시행**. 목표 달성으로 쓰지 않는다.

| 시험 | 방법 | 결과 |
|---|---|---|
| Pi 새 중계 | `scp pi_relay.py group10@group10.local:~/sharekey/` → Pi에서 실행 | `문 상태 알림 port=9101` 나옴 |
| 보드 판 확인 (Pi 경유) | RESET | `boot F429 vehicle control v2`, `MODE=C`, **`DOOR STATE OPEN`** → `_v6` 확인 |
| Pi 중계 OFFLINE ① | `--server 172.20.10.11:9000` | `no server response -> OFFLINE` → **Pi IP를 넣은 실수**. 노트북 IP로 고쳐 `ONLINE` |
| Pi 중계 OFFLINE ② | 노트북 중계 → Pi로 옮김 | 서버를 안 켜 둔 상태 → 서버 켜고 중계 다시 → `ONLINE` |
| 위조 요청 (웹) | 키 A, 위조된 요청 보내기 | REQ → CHAL → RESP(서명 첫 바이트 `E1`→`E0`, 1비트) → **거부 01, 남은 4** (횟수 안 깎임) |
| **`_v7` A 전환** (노트북 중계) | USER 누른 채 RESET | OLED **`LEFT INF`**(제한 없음) 확인 → A 방식 동작 |
| **C 오프라인 취소** (Pi 경유, 18:18 웹 화면) | 키 A 발급·등록 → 차량 오프라인 → 취소 → 문 열기 반복 | 웹 "키 취소 뒤 오프라인에서 허용된 횟수 **4 / 10회 시도**", "거부 · 잠김 유지 · 오프라인 사용 한도 초과", 남은 오프라인 사용 0/4. 보드 판(`_v6`/`_v7`)은 화면에 안 나옴 |
| 웹 초기화 | 서버만 다시 켬 | 기록 그대로 → `Remove-Item` + 브라우저 새 탭 필요 |

- 확인 못 한 것: **`_v7` A로 오프라인 취소 뒤 6회 모두 허용**(`LEFT INF`까지만 봄, 결과 미보고), 그냥 RESET으로 C 복귀(`_v7`), 재전송 02(웹), 재요청 없는 `DENY 03`, 05 뒤 `WAIT/LEFT 4`, 정상 이용자 오프라인 C, 서보 실제 각도(900/2100 적용 여부 포함), Pi 경유 웹 문 그림 움직임, 키 한도 넘김(실물), 중간발표 현장 결과

## 8. 참고 (사용한 자료, AI 대화에서 나온 중요한 내용)
- 중간발표 PPT `4조_…_1107.pdf`(8장), 대본 docx, 곽동규 작업 정리 1106, `04_purchase_list.md`(10/27판: 끝점 센서 없음, Grove Micro Switch는 문 닫힘용)
- **USER 버튼 전환(`_v7`):** 그냥 RESET = C / USER 누른 채 RESET → OLED 첫 글자 `A`일 때 떼기 = A. 계속 누르면 1.5초마다 A↔C. 목록 `"CA"`뿐(B·D는 RTC 뒤). RESET하면 키 재등록
- **펌웨어 바꾸기(Pi 경유일 때):** 배터리 빼기 → Pi 중계 `Ctrl+C` → USB를 노트북으로 → Run As(Console `.elf` 이름 확인) → USB를 Pi로 → 중계 다시 → RESET → 키 재등록. Run은 보드에 넣는 것이고 Pi에는 아무것도 안 들어감
- **`EST`:** 끝점 센서가 없어 서보 명령 후 0.5초(`SERVO_TRAVEL_MS`)로 위치를 추정. 판단 결과·문 닫힘(PF12)은 실제 값. 웹 "자동 잠금"도 명령 수락 로그 기준
- **`LEFT INF`:** A 방식, 남은 횟수 제한 없음(RES `FF`)
- **재전송 02:** 같은 키로 문 열기가 한 번 성공해야 동작(앱이 성공한 응답만 저장). 새 키로 바로 누르면 "재전송할 이전 응답 없음", 차에는 안 보냄
- **독창성 표현:** 개별 방식(C 등)·HMAC·nonce는 기존 기술. 차별점은 "취소 뒤 공백"을 차 쪽에서 여러 방식으로 **같은 조건에서 비교·정량화**해 선택 근거를 주는 것(결과 전에는 "근거를 제공한다/도울 수 있다")
- 비밀번호·Wi-Fi 정보는 기록하지 않음
