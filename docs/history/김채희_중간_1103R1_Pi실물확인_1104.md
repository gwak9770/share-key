# 김채희 중간 공유 — 1103 R1 + 웹, 실물 Pi 경유 확인

> 2026-11-04 · 기준 문서 00_master_design.md **v0.3.9** · 받는 사람: 권기백(11/5 판정), 곽동규, 조민선
> 공유 코드는 안 고침. 복사본 **`sharekey_f429_OLED_v3`**에 기백 1103 R1 8개 파일 적용 (1102 판 `_v2`는 보관)

## 적용·연결
- `VC_DEMO_MODE_SELECT 0` 그대로 → 빌드 → Run As → Download verified
- 노트북 `server.py`·`web_app.py` → Wi-Fi → **실물 Pi 5 `pi_relay.py`** → USB(CN1) → 보드. 탭 B에 `ONLINE`
- 서보 SG90 + 4구 AA, OLED 2.42" (보드 I2C1), 문 스위치 = 택트 스위치(PF12)

## 결과 (각 1회, 김채희 관찰)
| 시험 | 결과 |
|---|---|
| 키 등록 (웹) | Pi 로그 `KEY ok kid=00000007 limit=4`, 웹 `7번 유효 · 차 등록` |
| OLED `KEY OK` | 처음엔 **OLED가 `C / WAIT / LEFT -- / UNKNOWN`에서 멈춤** (서보는 움직임, RESET해도 그대로) → **OLED VCC 선을 뺐다 꽂고 RESET** 후 `KEY OK` 표시 |
| 온라인 열기 + 다시 잠그기 | 문 열기 → 서보 열림·OLED 바뀜 → 스위치 뗐다 누름 → 서보 잠금. 여러 번 성공 (**10회 연속은 안 함**) |
| **오프라인 C + 다시 잠그기** | 오프라인 → 키 취소 → 열기 6회: **허용 4회(LEFT 3·2·1·0), 매번 서보 열림→잠금**, 5·6회 **05** → 온라인 후 **03**. **C 4/6, 이번엔 FAULT 없음** |

## 알게 된 것 (추정, 확인 안 됨)
- OLED 멈춤: I2C 통신이 한 번 끊기면(서보 잡음·접촉 추정) 보드 RESET으로는 OLED 칩이 안 풀림. OLED는 3V3에서 계속 전원을 받기 때문 → **OLED 전원을 껐다 켜야 풀림**. 재현 시험은 안 함
- 다시 잠그기는 스위치를 집게로 계속 물려 두면 동작 안 함 (뗐다 눌러야 '닫힘' 감지)

## 요청
- **권기백**: 다시 잠그기 11/5 판정 **"사용" 제안 유지**. 10회 연속은 문짝 단 뒤 확인 예정
- **곽동규**: OLED 멈춤 대비 검토 부탁 (예: 다시 연결할 때 I2C 버스 풀기). **코드 변경은 판단 후 요청**
- **조민선**: OLED 선 짧게·단단히, 서보 선과 떨어뜨리기. 문짝이 스위치를 확실히 누르는 구조

## 아직 안 한 것
- 다시 잠그기 10회 연속 (문짝 단 뒤) · ④ USER 버튼 A/C 전환 · ⑤ 웹 C/A 캡처 · ⑥ FAULT → RESET 복구 · OLED 멈춤 재현
