# 곽동규 중간 공유 — R1 수정판 적용 및 재잠금 시험 안내

> 날짜: 2026-11-04 · 기준 문서: 00_master_design.md v0.3.9
> 전달 대상: 권기백, 김채희, 조민선
> **곽동규는 STM32 제어 코드 검토·시험 결과 정리 및 실물 테스트 지원 담당이며, 발표자가 아닙니다.**

## 1. 한 일 (요약 3줄 이내)

- 카카오톡 받은 파일의 채희 실물 보고서와 웹 코드, 앞서 추출한 R1 보드 코드를 확인하고 전달 안내와 대조했습니다.
- 1102 판 실물 성공과 R1 수정판 PC 검증을 구분했으며, 스위치를 계속 누른 채 시험하라는 안내의 보완 사항을 정리했습니다.
- 이번 공유 문서는 팀원 전달용입니다. 이번 정리 과정에서 생산 코드 변경·보드 업로드·실물 시험은 하지 않았습니다.

## 2. 결정한 것 / 공통으로 확인할 사항

| 항목 | 공유 내용 | 이유 |
|---|---|---|
| 가장 중요한 안내 정정 | **스위치를 시험 내내 누른 채 고정하면 재잠금이 발생하지 않습니다. 매회 해제 완료 → 스위치 놓기 → 다시 누르기 → 잠금 완료까지 유지해야 합니다.** | 코드는 문 열림→닫힘 변화를 감지하여 재잠금을 요청합니다. |
| 기본 실물 시험 | VC_DEMO_MODE_SELECT=0 유지, C 모드로 진행 | 등록·재잠금 반복부터 확인하는 기존 안내를 따릅니다. |
| A/C 전환 | 현재 설정 0에서는 비활성 | 웹에 USER 버튼 전환 설명이 있어도 보드 기능이 켜지는 것은 아닙니다. |

| 10회 반복 시험 | 오프라인 횟수 소진 후 온라인 복귀·동기화 확인, 반복 중에도 동기화 시간 확보 | 오프라인 상태로 계속하면 횟수 초과 거부가 발생합니다. |
| 원본 보존 | sharekey_f429_OLED_v2 통째로 백업 후 적용 | 문제 발생 시 검증한 기존 판으로 복귀하기 위함입니다. |

## 3. 사용할 파일과 적용 방법

### 보드 코드 — 채희 적용

사용 파일: `stm32_vehicle_control_f429_v2_1103_R1수정_1104.zip`

같은 폴더에 있는 `_1104_1.zip`은 SHA-256 비교 결과 위 ZIP과 동일한 파일입니다. 이름의 `_1`은 내용상 추가 수정판을 의미하지 않습니다.

1. 현재 `sharekey_f429_OLED_v2`를 통째로 백업합니다.
2. R1 ZIP을 풀고 아래 8개 파일을 해당 프로젝트에 모두 덮어씁니다.
3. `VC_DEMO_MODE_SELECT=0`을 유지하고 기존 CubeMX 설정을 보존합니다.
4. Clean → Build(0 errors 확인) → Run As → 다운로드 성공 여부를 확인합니다.

| 적용 위치 | 파일 |
|---|---|
| Core/Inc | config.h, board.h, vehicle_app.h, vehicle_platform.h |
| Core/Src | board.c, port_stm32.c, vehicle_app.c, oled.c |

설명은 ZIP의 `docs/KEYOK_1103_KO.md`를 참고합니다. **1102 판을 적용한 채희 보고서의 4개 파일 목록과 이번 R1 후보판의 8개 파일 목록은 적용 버전이 다릅니다. 이번에는 8개를 적용합니다.**

### 웹 화면 — 보드가 연결된 노트북에서 실행

사용 파일: `sharekey_웹화면포함_1104.zip`

압축을 풀고, PowerShell 창 3개를 각각 같은 `sharekey` 폴더에서 엽니다. 이미 실행 중인 기존 서버·중계와 중복 실행하지 않습니다.

| 창 | 실행 명령 | 역할 |
|---|---|---|
| 1 | `python server.py` | 키 발급·취소 및 서버 동기화 |
| 2 | `python pi_relay.py --serial COM4` | 보드 통신 및 HB 전송 |
| 3 | `python web_app.py` | 웹 화면 |

브라우저 접속 주소: http://127.0.0.1:8080

- COM4는 채희의 기존 연결 기준입니다. 다른 노트북에서는 실제 보드 COM 번호를 확인합니다.
- 웹 자체는 Python 기본 기능을 사용하고, 시리얼 중계에는 pyserial이 필요합니다.
- 전달받은 운영 절차대로 서버나 중계를 다시 켠 경우 보드 RESET 후 키를 다시 등록합니다. RESET하면 보드 RAM의 키·횟수 상태가 초기화됩니다.
- 이 실행 방식은 노트북과 보드의 직접 연결입니다. Pi 경유 시험 완료로 기록하지 않습니다.

## 4. 전체 설계와 다른 점 / 안내 정정

설계를 바꾸는 요청이 아니라 기존 코드 동작에 맞게 시험 절차를 명확히 하는 내용입니다.

**기존 표현:** “스위치는 테이프/집게로 눌린 채 고정 → 문 열기 → 해제 → 다시 잠김”

**정정:** 테이프·집게는 매회 문 닫힘을 만든 다음 눌림을 유지하는 용도입니다. 해제 후 스위치를 놓았다가 다시 눌러야 문 열림→닫힘 변화가 생깁니다. 처음부터 계속 눌린 상태로는 자동 재잠금 조건이 만들어지지 않습니다.

잠금 동작 중 스위치가 풀리면 `DOOR_OPEN` 오류가 발생할 수 있으므로 잠금 완료까지 확실히 유지합니다. 실제 문 모형은 **문을 열면 스위치가 풀리고, 문을 닫으면 계속 눌리는 구조**로 제작합니다. 이 입력 문제를 해결하기 위해 안전 차단 코드를 임의로 해제하지 않습니다.

## 5. 확인된 결과와 아직 확인하지 않은 결과

| 대상 | 확인 내용 | 근거 및 한계 |
|---|---|---|
| 1102 판 재잠금 | 온라인에서 서보 해제↔잠금 5회 연속 성공 | 채희의 11/4 실물 보고서에 기록된 결과 |
| 1102 판 큰 글자 OLED | 실물 출력 확인 | 큰 글자 화면에는 문 열림·닫힘 표시가 별도로 없음 |
| 1102 판 오프라인 C | 판단은 4회 허용 후 05 거부 | 재잠금 도중 스위치가 풀려 FAULT 발생. **4회 모두 실제 왕복 성공한 것은 아님** |
| R1 수정판 | 호스트 시험 19개 구성 통과 | 기존 PC 실행 로그. 이번 문서 작성 중 재실행하지 않음 |
| R1의 오래된 HB 문제 | 오래된 HB로 구동 차단, 새 HB 뒤 구동 확인 | 추가 PC 재현 검사. fresh=0/LINK_STALE → 새 HB 후 ACT=OK |
| R1 적용 안내 | 8개 파일 복사·15초 자동 확정 설명 보완 | 수정판 문서 및 코드 확인 |
| R1 실물 | 아직 확인 결과를 받지 못함 | 1102 판의 실물 성공을 R1 전체의 성공으로 확대하지 않음 |
| 웹 화면 | 실행 명령·기본 주소·관련 코드 확인 | 실제 보드와 연결한 웹 시험은 이번 확인에서 수행하지 않음 |
| Pi 경유·A 모드 | 채희 보고서 기준 미실시 | 이후 시험 결과를 별도로 기록해야 함 |

## 6. 막힌 점 / 확인이 필요한 사항

- 오프라인 C에서 해제·재잠금을 오류 없이 4회 수행하는 실물 확인이 남아 있습니다.
- 문·스위치를 고정한 상태에서 재잠금 10회 반복 확인이 필요합니다.
- `DOOR_OPEN` 발생 시 기존 안내대로 RESET 후 재등록부터 시작합니다. 복구 성공 여부도 실제 확인 후 기록합니다.
- OLED에 문 상태를 추가하는 작업은 채희 보고서에서 필요 시 요청을 검토하는 단계이며, 이번에 확정하거나 구현한 사항이 아닙니다.

## 7. 다음에 할 일 — 시험 순서와 팀별 전달 사항

### 시험 순서

1. **R1 적용·등록:** 기본 C 모드 확인 → 웹에서 한도 4인 키 발급 및 보드 등록 → OLED `KEY OK` 확인.
2. **온라인 기본 동작:** 웹 문 열기 → 서보 해제 완료 확인 → 스위치를 놓고 잠시 유지 → 다시 누르고 잠금 완료까지 유지. 로그와 실제 서보 동작을 함께 확인.
3. **오프라인 준비:** 사용 가능한 횟수가 4로 준비된 상태에서 시작. 앞선 시험의 소진 상태를 그대로 쓰지 않도록 새 키를 발급·등록하거나 온라인 동기화를 확인한 뒤 차량 오프라인으로 전환. 전환 직후 곧바로 요청하지 말고 오프라인 반영을 확인.
4. **오프라인 C 6회 요청:** 1~4번째 요청마다 해제→스위치 놓기→다시 누르기→재잠금 수행. 남은 횟수 3→2→1→0 확인. 5·6번째는 `DENY 05` 및 서보 구동 없음 확인. 중계와 HB는 계속 유지.
5. **온라인 복귀 후 10회 반복:** 온라인으로 복귀하고 동기화 확인. 각 회차 해제·재잠금 완료와 동기화 시간을 확보하며 10회 수행. 정상/실패 횟수와 오류 로그 기록.
6. **결과 공유:** 코드 버전, 설정값, 연결 방식, 시험 횟수, 로그, 실제 서보 움직임을 함께 전달. 실패하면 어느 단계에서 발생했는지 명시.
