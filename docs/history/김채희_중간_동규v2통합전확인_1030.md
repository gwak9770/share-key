## 확인이 필요한 것 (통합 빌드 전에)
1. **공유 코드 교체:** v2는 `port_stm32.c`를 **다시 작성**하고, `sk_app_run()`을 새 파일 `vehicle_app.c`로 옮겼다.
   - `port_stm32.c`는 공유 코드(sharekey/stm32)라 00 규칙상 **팀장 승인 후** 교체해야 함
   - sharekey.c, sk_crypto.c는 "변경 없는 사본"이라고 적혀 있음 (해시 기록) → 판단 규칙은 그대로로 보임
2. **역할 겹침:** v2의 `vehicle_app.c`가 "인증 결과와 제어 연결"을 맡음. 00 §4상 조민선 담당인 `sk_port_actuate/deny`와 겹침 → 누가 어느 부분을 맡을지 정리 필요
3. **HB 필수:** v2는 실제 `RID|HB`가 2초 안 오면 구동 차단·오류 유지
   - `pi_relay.py`는 이미 250ms마다 HB를 보냄 (코드 확인함) → Pi·노트북 중계 경로는 문제없어 보임
   - **miniterm으로 직접 시험할 때는 HB가 없어 서보가 안 움직일 수 있음** (v2 `tools/bench_console.py` 사용)
   - Pi의 `~/sharekey/pi_relay.py`가 HB 포함 버전인지 확인 필요

## 결정 요청 (권기백)
- v2의 `port_stm32.c` 교체를 승인할지
- 승인하면: 김채희 노트북에서 `sharekey_f429` **복사본**에 적용(원본 보관) → 기존 A·C 결과 재확인 → 서보 연결
