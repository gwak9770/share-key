## 1. 한 일 (요약 3줄 이내)

- 이전 작업을 이어 Pi의 Python·pyserial을 확인하고, 공유 Python 코드의 별도 사본으로 Pi 내부 A·C 자동 중계 모의시험을 수행했다.
- Windows 서버·앱과 Pi 중계·Python STM32 시뮬레이터를 네트워크로 연결해 키 등록, 정상 인증, C 방식 오프라인 횟수 제한 및 동기화 후 취소 반영을 확인했다.
- 같은 네트워크 경로에서 변조·재전송 거부를 각각 1건 확인했다. 실제 STM32는 연결하지 않았으며, 실물 통신·제어 및 반복 성능 목표는 미검증이다.

## 4. 전체 설계와 다른 점 (중요)

- 메시지 형식, 판단 순서, 사유 코드, 핀 배치, 공유 파일 구조 변경: **없음**.
- 시험 환경 차이: v0.3의 노트북 표기는 macOS이지만 이번 작업은 Windows 11에서 수행했다. 확인한 명령 범위에서 동작했으며 전체 Windows 호환성을 검증한 것은 아니다.
- 실물 구성과의 차이: STM32를 연결하지 않고 Python STM32 시뮬레이터를 사용했다. 기존 공유 코드가 지원하는 모의시험 경로이며 실물 완료로 간주하지 않는다.
- 역할 표기 차이: v0.3 §4에는 곽동규가 STM32 통합·발표, 김채희가 Pi 중계·AI로 기재되어 있다. 이번 사용자가 지정한 업무는 곽동규의 Pi 세팅이다. 팀 역할표를 임의로 수정하지 않았고 최신 문서 대조가 필요하다.
- USB–TTL 검정·흰색·초록 선 연결을 문의받아, 해당 색상 규격의 케이블에 한해 Pi 물리 핀 6·8·10 대응을 안내했다. 실제 제품 규격·배선 사진·UART 통신 결과는 확인하지 못했다. 이는 Pi 콘솔용 안내이며 기준 설계의 Pi–STM32 ST-LINK USB 연결을 대체하지 않는다.
- 일정 변경 결정: 없음. 오늘 결과는 모의시험 단계이며 실물 통합 일정 달성 여부를 확인하지 않았다.
- **코드·설계 변경 요청: 현재 없음.** 최신 기준 문서 제공 및 역할 범위 확인 요청은 아래 미해결 항목으로 관리한다.

**주요 원문 출력 발췌**

Pi 실행 환경:

```text
Python 3.13.5
pyserial: 3.5
```

Pi 내부 자동 시연:

```text
방식 A: 취소 후 추가 사용 6회 / 6회 시도
방식 C: 취소 후 추가 사용 4회 / 6회 시도
```

Windows–Pi 분리 C 시험:

```text
=== 취소 후 1 번째 요청 ===
[앱] 문열기: 허용 (정상) 남은횟수=3
=== 취소 후 2 번째 요청 ===
[앱] 문열기: 허용 (정상) 남은횟수=2
=== 취소 후 3 번째 요청 ===
[앱] 문열기: 허용 (정상) 남은횟수=1
=== 취소 후 4 번째 요청 ===
[앱] 문열기: 허용 (정상) 남은횟수=0
=== 취소 후 5 번째 요청 ===
[앱] 문열기: 거부 (오프라인 횟수 초과) 남은횟수=0
[시연] 서버↔차량 연결
[앱] 문열기: 거부 (취소된 키) 남은횟수=0
```

Windows–Pi 분리 변조·재전송 시험:

```text
[주인 앱] KID=00000008 발급 (한도 4, 24시간)
[앱] 차량 키 등록: 성공
[앱] 문열기: 허용 (정상) 남은횟수=3
[앱] 문열기: 거부 (인증값 불일치) 남은횟수=3
[앱] 문열기: 거부 (nonce 만료·재사용) 남은횟수=4
```

**해석 및 제한**

- C 방식의 오프라인 거부는 사전에 정한 횟수 한도 소진 때문이며 취소 탐지 결과가 아니다. 동기화 후의 취소 거부와 구분한다.
- 재전송 시 남은횟수가 3에서 4로 표시된 것은 온라인 상태의 주기적인 인증된 동기화에 따른 복구로 추정된다. 해당 시점의 동기화 로그를 대조하지 않았으므로 복구 시점·원인은 확정하지 않는다. 재전송 요청 자체는 명확히 거부됐다.
- 자동 시연 종료 시 출력된 STM32 연결 끊김은 확인한 demo.py의 시뮬레이터 선종료 순서와 일치한다. 이 로그를 실물 케이블 장애로 해석하지 않는다.
- 자동 로그의 문열기 실행·LCD 표시는 시뮬레이터 문자열이다. 실제 구동기·표시장치 작동을 확인한 것이 아니다.
- net off/on은 애플리케이션에서 동기화 응답을 중단·재개하는 시험이다. Wi-Fi 물리 단절이나 Windows 방화벽 차단 시험은 하지 않았다.
- 이번에는 --relay의 Python 시뮬레이터를 사용했다. --relay-c의 C 코드 실행 및 Python/C 결과 동등성은 오늘 검증하지 않았다.
- 반복 횟수, 지연, 오탐률 등의 목표 달성이나 보안성 전체를 주장할 근거는 확보하지 않았다.

**핵심 실행 명령**

Pi 내부 자동 시연은 별도 시험 폴더에서 다음과 같이 실행했다.

```bash
python3 -u demo.py --relay 2>&1 | tee demo_relay.log
```

네트워크 분리 시험에서는 Windows 서버 창, Pi 시뮬레이터 창, Pi 중계 창을 각각 유지하고 별도의 Windows 앱 창에서 요청했다.

```powershell
# Windows 시험 폴더: 서버
python -u server.py
```

```bash
# Pi 시험 폴더: 서로 다른 터미널에서 실행
python3 -u stm32_sim.py --mode C
python3 -u pi_relay.py --sim 127.0.0.1:9200 --server 172.20.10.3:9000
```

Windows 앱은 기본 서버 주소 127.0.0.1:9000을 사용하고, 차량 대상만 --vehicle 172.20.10.11:9100으로 지정했다. app.py net off/on은 Wi-Fi를 끄는 명령이 아니라 시험 서버의 차량 동기화 응답을 제어하는 명령이다.
