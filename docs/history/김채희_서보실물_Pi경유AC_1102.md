## 1. 한 일 (요약 3줄 이내)
- 노트북 한 대에서 SSH로 Pi를 다루며, 4구 AA 홀더로 **SG90 서보를 연결해 처음으로 실물 동작을 확인**했다(허용 → 반시계 회전).
- **노트북 → Wi-Fi → Pi 5 → F429(v2) + 서보** 구성으로 C·A를 각 1회 시연했다: 취소 후 추가 사용 **C 4/6, A 6/6**, 변조 01·재전송 02·동기화 후 03.
- 발표용 터미널 캡처를 찍고(C·A), A 영상은 녹화했다(조민선). 이어서 복사본 `sharekey_f429_OLED`로 **2.42" SSD1309 OLED 8줄 표시와 open/tamper 때 AUTH 줄 변화**를 확인했다.

## 2. 결정한 것
| 항목 | 결정 | 이유 |
|---|---|---|
| Pi 조작 | 곽동규 대신 **김채희 노트북에서 SSH**(`ssh group10@group10.local`)로 Pi 중계 실행 | 노트북 한 대로 보드·Pi를 다 다룸. 동규는 발표 준비에 집중. 00 §4 역할 유연 원칙 |

| 전원 순서 | **켤 때 USB → 건전지 / 끌 때·USB 옮길 때 건전지 → USB** | 보드가 꺼진 상태에서 서보만 전원을 받으면 신호선이 떠서 서보가 제멋대로 돎 |

## 5. 시험 결과
모두 **1회 시행**. T01~T07 목표 달성으로 쓰지 않는다.

| 시험 | 방법 | 결과 (캡처) |
|---|---|---|
| Pi 원격 접속 | `ssh group10@group10.local` | 접속 성공, Pi IP 172.20.10.11, `pi_relay.py`에 `def heartbeat()`(116행)·실행(130행) 확인 |
| Pi 포트 | `python3 -m serial.tools.list_ports -v` | `/dev/ttyACM0` STM32 STLink, SER=066CFF515250898367132854 |
| Pi → 노트북 서버 | `socket.create_connection(('172.20.10.12', 9000))` | 처음 timed out → 노트북 쪽 확인 후 OK |
| **서보 실물** (노트북 직결 COM4) | issue → register → open | **서보 반시계 회전(약 20도, 김채희 관찰)**. 로그 `AUTH ALLOW CMD=01 LEFT=3 ACT=OK` → `ACT DONE POSITION=UNLOCKED SOURCE=ESTIMATED`. 이후 open은 이미 해제 위치라 움직임 없음 |
| **Pi 경유 C** (v2, 서보 연결) | 노트북 server·app(`--vehicle 172.20.10.11:9100`), Pi `pi_relay.py --serial /dev/ttyACM0 --server 172.20.10.12:9000` | 아래 표 |
| **Pi 경유 A** | `config.h` `'A'` 빌드, 같은 순서 | 아래 표 |
| C로 되돌림 | `'C'` 빌드·업로드, RESET | `MODE=C ENDPOINTS=0 SERVO=1 MOTOR=0 TEST=0`, ONLINE |
| **OLED** (복사본 `sharekey_f429_OLED`, 노트북 직결) | OLED GND–GND, VCC–3V3, SCL–D15(PB8), SDA–D14(PB9), RES 미연결. Build(0 errors) → Run As | **8줄 표시** `F429 CONTROL / AUTH` · `ARM 0 READY 1` · `DOOR OPEN`(문 스위치 미연결) · `POS UNKNOWN SENSOR` · `MOTOR 0 MOVE 0` · `NONE` · `AUTH - WHY -- LEFT -1` · `ACT NONE / RTC INVALID` (사진). open·tamper 후 AUTH 줄이 바뀜(김채희 관찰) |

| 요청 | C (17:11~17:13) | A (17:30~17:31) |
|---|---|---|
| 부팅 | `MODE=C` | `MODE=A` |
| register 7 | `KEY ok ... limit=4` | `KEY ok ... limit=4` |
| open (온라인) | 허용, 남은 3, `ACT=OK` | 허용, **제한없음**(`LEFT=-1`), `ACT=OK` |
| tamper / replay | 거부 01 / 02 | 거부 01 / 02 |
| net off → revoke → open ×6 | 1~4회 허용(3→2→1→0, `ACT=OK`), 5·6회 **05** | **6회 모두 허용**, 매번 `ACT=OK` |
| net on → open | `SYNC applied ver 1 -> 2`, 거부 **03** | `SYNC applied ver 1 -> 2`, 거부 **03** |
| **취소 후 추가 사용** | **4/6** | **6/6** |

- 00 §9의 PC 결과, 10/28 실물 결과, 10/30 v2 노트북 직결 결과와 같음
- C의 5·6회 거부는 공유 때 정한 한도 소진(05)이며 취소를 알아낸 것이 아님. 취소 반영은 재연결 후 인증된 동기화(03)
- `SOURCE=ESTIMATED`는 끝점 센서가 꺼져 있어 시간으로 추정한 위치. 첫 open의 실제 회전은 눈으로 봄, 이후는 로그만
- 진행 중 생긴 로그와 원인 (모두 해결)
  | 로그 | 원인 | 조치 |
  |---|---|---|
  | `RX DROP invalid/overlength line`, `받을 앱이 없는 응답`, `형식 오류 줄 무시` | 중계가 포트를 여는 순간 반쯤 들어온 글자 | 시작 때 1~2줄만이면 무시 |
  | `ACT=FAULT` (17:06) | 접속 시험하려고 중계를 끈 동안 HB 끊김 → v2 오류 유지 | 중계 재실행 + 보드 RESET |
  | `SYNC rejected (nonce/ver/tag)` 반복 | 서버를 VER 0으로 새로 켰는데 보드는 VER 2 기억 → 00 §6-5대로 거부 | 보드 RESET |
  | 서보가 혼자 돎 | USB를 뽑은 상태에서 건전지만 연결 → 신호선이 떠 있음 | 전원 순서 지킴 |
  | 중계 `Stopped` | Pi 창에 앱 명령을 잘못 입력하고 Ctrl+Z | `kill %1` 후 재실행 (멈춘 작업은 `kill -9 %1`로 정리 필요) |
- 확인 못 한 것: 서보 1200↔1800 실제 각도, 걸쇠 달린 상태, 다시 잠그기(미구현), 모터·센서·OLED, 재부팅 후 상태(저장 미구현), A 영상 재생 확인
