## 모터 4개 동시 구동 개선

11/19에는 AA 알카라인 4개와 약 40% 듀티에서 2개씩 구동에는 성공했으나, 바퀴 4개를 함께 돌리면 저속·조기 정지·일부 바퀴 미구동이 나타났다. 당시 MDD3A 입력 전압은 정지 5.5V, 왼쪽 2개 4.6V, 오른쪽 2개 4.7V, 전체 4.2V였다. 전체 구동 시 1.3V(정지 기준 약 23.6%, 계산값)가 떨어졌다. [11/19 전압 원기록](../2026-11-19_motor_bench/voltage.csv)

11/26에는 동일한 4구 홀더·드라이버·모터 배선을 유지하고 Panasonic eneloop AA 니켈수소 충전지 4개로 교체했다. 공칭 전압은 셀당 1.2V, 직렬 합계 4.8V다. 40%에서 4개 회전은 가능했으나 저속과 일부 바퀴 미구동이 재현됐다. 기동 토크가 부족할 가능성을 보고 듀티를 60%로 높였다. 버튼 방식과 500ms 제한은 유지했다.

| 관찰 항목 | 11/19 알카라인 40% | 11/26 eneloop 40% | 11/26 eneloop 60% |
|---|---|---|---|
| 왼쪽 / 오른쪽 모터 2개씩 | 양쪽 정상 | 양쪽 정상 | 양쪽 정상 |
| 전체 모터 4개 | 불안정, 조기 정지 포함 | 회전했으나 불안정 | 3회 중 3회 정상 |
| 저속 | 발생 | 발생 | 최종 시험에서 정상 구동 관찰 |
| 간헐적 일부 바퀴 미구동 | 발생 | 발생 | 최종 시험에서 관찰되지 않음 |

60%에서는 모든 바퀴의 전진 방향 일치, 버튼 해제 시 즉시 정지, 버튼 유지 시 500ms 자동 정지를 관찰했다. 정지 시간과 펄스 파형은 계측하지 않았다. 시험 중 이상 소음·발열·냄새 관찰은 없었다. 4개 동시 구동 3회 외 항목별 시행 횟수는 미상이다.

듀티를 높인 뒤 상황이 개선된 결과는 기동 토크 부족 가설과 일치한다. 멀티미터가 없어 11/26 전압·전류는 미측정이며, 충전지 교체 후 전압 강하의 변화량도 미상이다. 알카라인 60% 조건은 미수행이다. 공급 능력·홀더 접촉 저항·듀티의 영향을 분리하지 못해 근본 원인 및 충전지의 독립 효과는 미확정이다. 바퀴를 공중에 띄운 무부하 단시간 시험으로, 지면 주행과 장시간 구동은 미검증이다.

## DS3231 배선과 설정

사용자가 확인한 Raspberry Pi용 5핀 모듈 표기는 왼쪽부터 `+`, `D`, `C`, `NC`, `-`다.

| 모듈 표기 | STM32 보드 표기 | 역할 |
|---|---|---|
| `+` | 3V3 | 3.3V 전원 |
| `D` | PB9 / D14 | I²C1 데이터(SDA) |
| `C` | PB8 / D15 | I²C1 클록(SCL) |
| `NC` | 미연결 | 미사용 |
| `-` | GND | 접지 |

D14·D15 표기는 팀 설계와 ST 공식 핀 표에서 교차 확인했다. [00 설계 §8](../../00_master_design.md#8-하드웨어) · [ST UM1974 표 17](https://www.st.com/resource/en/user_manual/um1974-stm32-nucleo144-boards-mb1137-stmicroelectronics.pdf#page=55)

CubeMX에서 I²C1을 추가하고 초기 SCL 선택 PB6을 실제 배선에 맞춰 PB8로 바꿨다. 최종 IOC는 PB8/PB9를 선택한다. 생성된 초기화 코드는 표준 모드 100kHz, 7비트 주소, 대체 기능(AF4) 오픈드레인, 내부 풀업·풀다운 없음, 아날로그 필터 켬과 디지털 필터 0을 설정한다. 풀업 구성의 실측은 미수행이다. 기존 모터 GPIO인 PE9(M1A)·PE11(M1B)·PE13(M2A)·PE14(M2B)와 PC13(USER 버튼)을 유지했다. IOC의 `KeepUserCode=true`와 재생성 후 60% 구동 코드가 남아 있음을 확인했다.

## RTC 시험 순서와 결과

| 단계 | 방법과 관찰 | 판정 |
|---|---|---|
| 주소 응답 | `HAL_I2C_IsDeviceReady()`에 7비트 주소 `0x68`을 `0x68 << 1`로 전달. 처음에는 PB14의 빨간 LD3만 켜짐. 소프트웨어 변경 없이 양쪽 점퍼선을 다시 끼운 뒤 PB0의 초록 LD1이 켜짐. | 첫 시도 실패, 재시험 성공. 접촉·연결 상태가 원인일 가능성이 있으나 위치·원인은 미확정. |
| 초 레지스터 | `HAL_I2C_Mem_Read()`로 `0x00`을 읽고 `HAL_Delay(2000)` 후 재읽기. 이진화 십진수(BCD)를 변환하고 `(sec2 + 60 - sec1) % 60`으로 분 경계를 처리. | 초록 LD1. 초 증가 성공. 관측 원시값과 실제 분 경계 시험 여부는 미상. |
| 발진기 정지 플래그(OSF) 읽기 | 상태 레지스터 `0x0F`의 비트 7 확인. 초록 LD1과 빨간 LD3가 함께 켜짐. | 초 증가와 OSF 1을 함께 관찰. 정지 이력의 원인은 미확정. |
| OSF 초기화 시험 | 상태를 읽어 `0x7F`로 비트 마스킹한 뒤 `HAL_I2C_Mem_Write()`로 기록하고 재읽기. | 초록 LD1만 켜짐. OSF 0 확인. |
| 30초 전원 차단 | 부팅 시 OSF를 지우는 임시 코드를 제거하고 재빌드·업로드. STM32 USB를 30초 분리한 뒤 다시 연결해 초 증가 및 OSF를 확인. | 1회 보고. 초록 LD1만 켜져 재연결 후 초 증가와 OSF 0을 확인. |

주소 확인용 호출과 OSF 쓰기는 이전 시험 단계의 사용자 보고다. 현재 확보한 소스는 최종 읽기 전용 판이다. 먼저 200ms를 기다린 뒤 초를 두 번 읽고 상태를 읽는다. 세 읽기가 모두 성공하고 변환한 초가 0~59이며 증가량이 1~3초일 때 LD1을 켠다. 이 조건에서 OSF가 1이면 LD3도 켜며, 읽기·범위·증가 조건 실패 시 LD3만 켠다. 단계별 총 시행 횟수는 별도로 알려진 경우 외 미상이다. [DS3231 데이터시트, 시간·상태 레지스터](https://www.analog.com/media/en/technical-documentation/data-sheets/ds3231.pdf)

### 현재 검증 범위

RTC 전원·배선 연결, I²C 주소 응답, 시간 레지스터 읽기와 증가, OSF 확인 및 시험용 초기화, USB 30초 차단 후 OSF 확인을 완료했다. 실제 날짜·시각 설정, 전원 차단 전후 시각값 직접 비교, 시간 오차와 백업 전압 계측, 디지털키 유효기간 연동은 미완료다. OSF는 재연결 후 0으로 읽혔다. 정확한 시각 유지·시간 조작 방지 검증에는 별도 시험이 필요하다. 통합 펌웨어에서는 신뢰할 수 있는 시각으로 동기화하고 타당성을 확인하기 전까지 OSF를 부팅 때 일괄 초기화하지 않는다.

사용자 보고 기준 해당 보드는 모터·RTC 시험판을 실행 중이다. 보드 읽기 및 업로드 로그 대조는 미수행이다. [시험판 소스 및 재빌드](../../../firmware/stm32/examples/mdd3a_motor_test_f429/README.md)
