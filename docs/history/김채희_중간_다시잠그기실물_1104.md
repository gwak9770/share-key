# 김채희 중간 공유 — 다시 잠그기(1102 판) 보드·실물 확인

> 2026-11-04 · 기준 문서 00_master_design.md **v0.3.9** · 받는 사람: 권기백(11/5 판정), 곽동규, 조민선
> 공유 코드·`sharekey_f429_OLED`(11/2판)는 안 고침. 복사본 **`sharekey_f429_OLED_v2`**에 곽동규 1102 판 4개 파일 적용

## 적용
- 곽동규 `stm32_f429_v2_relock_20261102_1.zip`: v2 대비 바뀐 파일 4개(`config.h`, `vehicle_platform.h`, `oled.c`, `vehicle_app.c`)만 덮어씀. 판단 파일 4개 해시 동일
- 기본값: 정책 C, SERVO 1, RELOCK 1, OLED 1, LARGE_TEXT 1
- CubeMX 그대로(TIM4 PD14, I2C1 PB8/PB9, `MX_TIM4_Init`·`MX_I2C1_Init` 호출 안 함) → 빌드 0 errors → Run As → Download verified
- 문 스위치: **키트 택트 스위치**, 대각선 다리를 **PF12(CN7 D8)**와 **GND**에. 누름 = 문 닫힘 (PF12 내부 풀업, `VC_DOOR_ACTIVE_LOW 1`)
- 연결: 노트북 직결(COM4, `pi_relay.py`로 HB 송신), 서보 SG90 + 4구 AA, OLED 2.42"

## 결과 (1회씩)
| 시험 | 결과 |
|---|---|
| OLED 큰 글자 | 4줄 표시(`C` / `WAIT·ALLOW·DENY` / `LEFT n` / `UNKNOWN·UNLOCK EST·LOCK EST`). 큰 글자 화면에는 **문 상태 표시 없음**(8줄 화면에만 있음) |
| **다시 잠그기 (온라인)** | open → `ACT=OK`·`UNLOCKED` → 스위치 누름 → **`DOOR CLOSED -> LOCK ACT=OK`·`LOCKED`**. 13:54~13:56 **5회 연속 반복 성공**, 서보 해제↔잠금 왕복(눈으로 확인) |
| 잠긴 뒤 스위치 뗌 | OLED `UNKNOWN` (코드대로: 잠긴 상태에서 문 열림 → 위치 모름) |
| 온라인 남은 횟수 | 계속 `LEFT 3` (동기화로 매번 4 복구, 정상) |
| **오프라인 C + 다시 잠그기** | 1회째 해제·잠금 시작 직후 **`CONTROL FAULT=DOOR_OPEN`**(잠그는 0.5초 안에 스위치가 떨어짐) → 이후 `ACT=FAULT`로 서보 막힘. **판단은 정상**: 허용 4회(LEFT 3·2·1·0) 후 05 × 2 → **C 4/6** |

## 알게 된 것 / 주의
- 잠그는 0.5초(`SERVO_TRAVEL_MS`) 동안 문 스위치가 떨어지면 FAULT_DOOR → **RESET으로만 풀림, RESET하면 키도 지워짐**(저장 미구현). 시연 중에 걸리면 등록부터 다시
- 손가락으로 누르면 일어나기 쉬움. 브레드보드 접촉 불량도 원인이 될 수 있음
- 문짝이 스위치를 **계속 누르는 구조**면 대부분 해결될 것으로 보임 (조민선 문·스위치 제작 시 확실히 눌리게)

## 판정 제안 (권기백)
- 다시 잠그기는 **보드에서 동작 확인** → 11/5 판정 "사용" 제안. 단, 문짝·스위치 고정 후 10회 반복 확인 필요(00 §7 문 만들기 7번)
- 큰 글자 화면에 문 상태가 없음 → 시연 중 원인 파악이 어려우면 동규에게 한 줄 표시 요청 검토

## 아직 안 한 것
- 오프라인 C를 다시 잠그기까지 **오류 없이** 끝까지 한 번
- 일부러 오류 낸 뒤 RESET 복구 확인 (진행 중)
- 기백 후보판 1103(KEY OK 표시, USER 버튼 A/C 전환), `web_app.py` — 파일 못 받음
