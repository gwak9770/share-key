## 5. 시험 결과
모두 **1회 시행**. 목표 달성으로 쓰지 않는다.

| 시험 | 방법 | 결과 |
|---|---|---|
| 1104 OLED 수정판 (`_v4`) | 노트북 직결, 등록 → 문 열기 → 스위치 뗐다 누름 | OLED `KEY OK`, 1줄 **`DOOR CL ↔ DOOR OP`**, 서보 잠김 `LOCK EST`. OLED 멈춤은 안 생겨서 **버스 복구 효과 미확인** |
| 노트북 중계 연습 (11/5) | `pi_relay.py --serial COM4 --server 127.0.0.1:9000` | 등록·열기·다시 잠그기 정상 |
| 실물 Pi 중계 (11/5) | Pi SSH | 처음 `no server response -> OFFLINE` → 원인: `--server`에 **Pi IP(172.20.10.11)** 입력. 노트북 IP로 고치라고 안내함 |
| 면담 시연 | — | 00 v0.3.11: **Pi 연결 문제로 못 보여 드림**(다음 면담 때). 김채희 쪽 기록은 위 IP 실수까지 |
| 1106 병합본 (`_v5`) | 노트북 중계, 온라인 문 열기 → 기다림 | **`LEFT 3 → 4` 자동 복구** (문 열기 다시 안 누름) |
| 1106 병합본 PC 시험 | AI 환경 gcc `-Wall -Wextra -Werror` | 호스트 19/19 통과(1106 실시간 표시 검사 + 1104 `DOOR` 검사 둘 다) |
| 기백 LIVE 판 (`_v6`) | 스위치 뗐다 누름 | 중계 창 **`[Pi] STM32: DOOR STATE OPEN / CLOSED`** |

| 서보 90도 보정 (동규 1106) | `config.h` `SERVO_LOCK_US 900u`, `SERVO_UNLOCK_US 2100u` (이전 1200/1800) | **받음, 실물 각도 미확인** |

## 8. 참고 (사용한 자료, AI 대화에서 나온 중요한 내용)
- 00_master_design.md v0.3.10 → v0.3.11(면담 반영, 4조, 포스터 8장), 곽동규 `oled_live_update_1106` README·`OLED_LIVE_1106.patch`, 권기백 `KEYOK_1103_KO.md` 1106 절, 곽동규 `servo_90_live_1106` README
- 노트북 중계 실행: 탭1 `python server.py` / 탭2 `python pi_relay.py --serial COM4 --server 127.0.0.1:9000` → 보드 RESET / 탭3 `python web_app.py --vehicle 127.0.0.1:9100`. 새 중계면 탭2에 `문 상태 알림 port=9101`
- 실물 Pi: 탭2 `ssh group10@group10.local` → `hostname -I` → `cd ~/sharekey` → `python3 pi_relay.py --serial /dev/ttyACM0 --server <노트북IP>:9000`. 웹 `--vehicle <Pi IP>:9100`. Pi의 `pi_relay.py`도 1106c로 바꿔야 웹 문 그림이 움직임
- 완전 초기화: 서버 `Ctrl+C` → `Remove-Item -Recurse -Force server_state.json, keys -ErrorAction SilentlyContinue` → 서버 → 중계 → 보드 RESET → 웹 → 브라우저 새 탭
- 1106 OLED: 온라인에서는 동기화(2초) 뒤 `LEFT 4`, 취소 동기화 뒤 `DENY 03 / LEFT 0`. OLED `LEFT`는 "실제 사용 가능 횟수"라 웹·로그의 원시 남은 횟수와 다를 수 있음(동규)
- 횟수 규칙(판단 코드 확인): 허용마다 항상 1 차감(`sharekey.c` 122행), 인증된 동기화 때만 limit로 복구(215행)
- 비밀번호·Wi-Fi 정보는 기록하지 않음
