## 1부. 플래시 반복 (§4.4-3)

한 묶음: 차량 온라인(횟수 복구) → 차량 오프라인 → 문 열기 4회 허용 → 5번째 05 → **RESET** → 차에 키 등록 → 문 열기 → 05 확인

| 항목 | 결과 |
|---|---|
| 수행 | 10회 |
| 성공 | 10/10 (재부팅·재등록 뒤에도 05, 남은 횟수 다시 채워짐 0) |
| 재부팅 방식 | RESET 버튼 |

## 2부. T04 재부팅 (§4.4-4)

한 묶음: 차량 온라인 → 차량 오프라인 → 문 열기(남은 3) → [재부팅 → 문 열기] ×4 (남은 2 → 1 → 0 → 05). 재등록 없이 보드가 플래시에서 키를 스스로 복원하는지 확인.

| 항목 | 결과 |
|---|---|
| 수행 | 10묶음 (안내 절차 기준 묶음당 재부팅 4회, 계 40회) |
| 재부팅 방식 | USB 완전 차단 5묶음, RESET 버튼 5묶음 |
| 결과 | 복원 실패(등록되지 않은 키) 0, 재부팅 뒤 남은 횟수 증가 0 |
| 중계 | USB 차단 뒤 COM4가 끊기면 `pi_relay.py`를 다시 실행 |

## 결과 요약

| 시험 | 목표 (02 §4.4) | 결과 |
|---|---|---|
| 플래시 반복 | 4회 소진 → RESET → 재등록 → 여전히 05, 실물 10회 | 10회 시행, 10/10 |
| T04 | 재부팅 30회 복원 실패 0, 재등록 뒤 증가 0 | 재부팅 50회(1부 10 + 2부 40) 시행, 복원 실패 0, 증가 0 |

- 회차별 남은 횟수 값과 각 회 시각은 기록하지 않았다. 결과는 시험자의 화면 확인 보고다.
- 저장 중 전원 차단(플래시 기록 도중 차단)은 하지 않았다. 이번 USB 차단은 기록이 끝난 뒤의 차단이다.
- 모터 출력은 이 빌드에서 꺼져 있다. 시동 관련 확인은 이번 범위가 아니다.

## 이상·관찰

- 1부·2부 모두 기대와 다른 결과 없음(시험자 보고). `C FAULT` 발생 없음.
- 시작 전 `register 31`이 `TimeoutError`로 실패했다. 원인은 보드에 독립 시험판이 올라가 있던 것이고, `sharekey_f429_OLED_v8` 재업로드 뒤 해결됐다.
- 11/27 독립 시험판은 RTC 시간을 한 번만 그려서 OLED 시간이 멈춘 것처럼 보인다. 그 판의 원래 동작이다.
