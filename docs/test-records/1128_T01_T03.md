## 시험 전 초기화

1. 시험자가 서버 상태(`server_state.json`, `keys/`)를 지우고 서버를 새로 시작했다.
2. 첫 확인 실행(14:31, `--count 5`)에서 T01 4개는 5/5 PASS. T03 키 등록이 `KEYNG … FF`로 실패했다. 보드 키 칸 8개가 다 찼기 때문이다(11/19부터 쓴 키가 플래시에 남아 있음).
3. `STM32_Programmer_CLI -c port=SWD -e 22 23`으로 플래시 저장 구역(섹터 22·23)만 지웠다. 다시 읽어 `FFFFFFFF`인 것을 확인했고, 펌웨어 영역은 지우지 않았다.
4. 보드가 `DENY 0A`(복구 필요)로 켜진 뒤 서버 승인 복구를 했다. `issue 30` → `recovery-request` → `recovery-issue 30 --new-kid 40` → `recovery-apply`(Pi 경유)에서 `복구 완료, 새 키 번호: 00000040` → `open 40` 허용(남은 3).

> 주의: 11/18 플래시 저장(PR #20) 이후로는 보드 RESET으로 키가 지워지지 않는다. 서버 상태만 지우면 서버와 보드가 어긋나므로, 서버 상태를 지울 때는 보드 저장 구역도 같이 초기화한다.
