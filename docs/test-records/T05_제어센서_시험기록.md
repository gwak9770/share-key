## 1. 목표 (00 §10, 아직 결과 아님)

| 항목 | 목표 |
|---|---|
| T05-1 | 허용(00)이면 서보가 해제되고, 문을 열면 문 열림을 감지한다 |
| T05-2 | 거부(03·08 등)이면 서보가 움직이지 않고 잠금을 유지한다 |
| T05-3 | 문을 닫으면 자동으로 다시 잠그는 동작이 **문짝을 단 상태에서 10회 연속** 성공한다 |

지금까지 기록: 11/4 김채희 보드에서 다시 잠그기 온라인 5회·오프라인 1회. 이때는 손으로 스위치를 눌렀다([기록](../history/김채희_다시잠그기_1103R1_Pi실물_1104.md)). 11/19에는 자동 재잠금 중 `C FAULT`(FAULT_DOOR)가 1회 났다(README 11/19 절).

## 2. 시작 전 준비 (모두 확인하고 체크)

- [ ] **문짝과 스위치 고정.** 아크릴 문이 닫히면 택트 스위치(PF12–GND)를 계속 누르게 만든다. 문이 저절로 떨어지지 않게 자석 등으로 닫힌 상태를 유지한다. 잠그는 약 0.5초(`SERVO_TRAVEL_MS 500`) 안에 스위치가 떨어지면 FAULT_DOOR가 난다.
- [ ] **서보 장착·각도 확인.** 펌웨어 값은 잠금 2000µs / 해제 1200µs(`config.h`)다. 걸쇠가 문에 걸리고 풀리는지 눈으로 본다. 값을 바꿔야 하면 바꾸지 말고 측정값만 적는다. 바꾸는 일은 별도 PR로 한다.
- [ ] **통합 펌웨어가 보드에 올라가 있음.** 독립 시험판(PR #42 `oled-rtc-servo-bench`)은 인증 판단을 하지 않으므로 이 시험에 쓸 수 없다. 김채희 님에게 main 기준 빌드·업로드를 부탁하고 **올린 커밋 7자리**를 받는다.
- [ ] **서보 전원.** 외부 전원 -와 Nucleo GND를 공통으로 연결하고, Nucleo 5V로 서보를 돌리지 않는다. PR #42의 MDD3A VB 분기 전원을 쓰면 그렇게 적는다.
- [ ] OLED 선은 짧게, 서보 선과 떨어뜨린다(11/4 OLED 멈춤 대책).

## 3. 실행 (노트북 직결 예시)

Pi를 쓰면 `--serial /dev/ttyACM0 --server <노트북IP>:9000`을 쓴다. 어느 구성으로 했는지 기록표에 적는다.

```sh
cd sharekey
# 탭1
python -X utf8 server.py
# 탭2 (COM 번호는 장치 관리자에서 확인)
python -X utf8 pi_relay.py --serial COM4
# 탭3
python -X utf8 app.py issue 7 --limit 4
python -X utf8 app.py register 7
```

웹(`web_app.py`)으로 해도 된다. 웹으로 했으면 그렇게 적는다.

## 4. 순서

**T05-1 허용 → 해제 → 문 열림 감지 (3회)**
1. 문 닫힘(스위치 눌림), OLED가 잠금 상태인지 본다.
2. `app.py open 7` 실행 → 결과 00, 서보 해제, OLED `ALLOW`·`UNLOCK EST`인지 본다.
3. 문을 연다(스위치 떨어짐) → 문 열림이 감지되는지(OLED·중계 로그 상태) 본다.
4. 문을 닫고 2초 유지 → 다시 잠기는지 본다(T05-3의 1회로 세지 않는다).

**T05-2 거부 → 잠금 유지 (각 3회)**
- 등록하지 않은 키: `app.py issue 8` 뒤 등록하지 않고 `app.py open 8` 실행 → **08** 거부, 서보 움직임 없음, OLED `DENY 08`.
- 취소한 키(온라인): `app.py revoke 7` 실행 → 동기화를 몇 초 기다린 뒤 `app.py open 7` → **03** 거부, 서보 움직임 없음.
- 끝나면 새 키 번호(예: 9)로 발급·등록해서 T05-3에 쓴다. 이미 쓴 번호를 다시 발급하지 않는다(README 11/19 알려진 문제).

**T05-3 다시 잠그기 10회 연속 (온라인)**
1. `app.py open 9` → 해제
2. 문을 연다 → 1초 이상 기다린다
3. 문을 닫는다 → 잠금 동작이 끝날 때까지 손을 대지 않는다
4. 잠김 확인(서보·OLED·로그) → 다음 회차
- 중간에 FAULT가 나면 그 회차는 실패로 적는다. 10회 연속은 처음부터 다시 센다. 실패 횟수도 지우지 않고 적는다.
- 온라인에서는 2초마다 동기화로 남은 횟수가 복구되므로 C 방식 횟수 소진은 신경 쓰지 않아도 된다.

## 6. 문제가 생기면

| 증상 | 대처 (11/4·11/19 기록 기준) |
|---|---|
| `C FAULT` (문 열림 중 잠금) | 원인(스위치 떨어짐·문 흔들림)을 적고 RESET. 키가 남아 있는지 확인하고, 없으면 새 번호로 다시 등록한다 |
| OLED 멈춤 | 서보 전원 빼기 → OLED VCC 선 뺐다 꽂기 → RESET → 키 다시 등록. 몇 회차에서 났는지 적는다 |
| 서버 응답 `ERR\|FF` | 9000번 포트에 서버가 두 개 떠 있는지 확인하고 하나만 띄운다 |
| 거부 상태에서 `LEFT INF` | 남은 횟수 값 -1 표시 문제다. 무제한이라는 뜻이 아니다 |
