# 곽동규 작업 정리 — F429 재잠금·OLED 큰 글자 구현 및 PC 시험

> 날짜: 2026-11-02 · 기준 문서: 00_master_design (2)(1).md **v0.3.5** + 권기백_중간_다시잠그기앞당김_OLED_1102.md
> **역할 정정: 곽동규는 발표자가 아닙니다.** 기존 마스터 §4·§15의 발표자 표기는 정정 대상입니다. 발표 담당자는 별도 확인이 필요합니다. 이번 작업의 담당 범위는 제어 코드·시험·기술 인계입니다.
> 갱신: 최초 재잠금판 작성 후 v0.3.5 원문과 OLED 실물 확인 보고서를 받아 반영했습니다. 적용 대상은 **sharekey_f429_OLED**입니다. 이전 보고서의 'v0.3.5 미확인·OLED 작업 보류' 상태는 해소됐습니다.

## 1. 한 일 (요약 3줄 이내)
- 기존 F429 v2에 디바운스된 문 열림→닫힘 재잠금과 OLED 3배 글자·4줄 화면을 구현했습니다.
- 실제 인증·판단 C 코드 및 가상 GPIO·I2C를 사용한 PC 시험 17개 구성이 모두 통과했습니다. 공유 인증 파일 4개의 원본 SHA-256 일치도 확인했습니다.
- 변경 패치·시험 로그·화면 미리보기·보드 적용 절차를 작성했습니다. 이번 수정본의 보드 빌드·업로드·실물 시험은 수행하지 않았습니다.

## 4. 전체 설계와 다른 점 (중요)

- 메시지 형식·판단 순서·사유 코드·핀·PWM 보정값·HB 시간·디바운스 시간 변경은 없습니다. `sharekey.c/h`, `sk_crypto.c/h`, `control.c`, `board.c`, `port_stm32.c`는 원본 그대로입니다.
- v0.3.5의 중간발표 전 다시 잠그기 및 OLED 큰 글자 요청을 코드와 PC 시험까지 이행했습니다. **새 코드의 스위치·서보·OLED 실물 동작이 확인됐다는 뜻은 아닙니다.**
- UNKNOWN 잠금 허용 제안은 적용하지 않았습니다. 실제로 UNLOCKED가 확인되는 경우만 허용하며, 끝점 센서 없는 기본 구성에서는 그 위치도 시간 기반 추정입니다.
- 명시적 정지로 `armed`가 해제된 상태에서 자동 재잠금이 제어를 다시 활성화하지 않도록 했습니다. 새로운 정책 판단이나 네트워크 명령을 추가한 것은 아닙니다.
- OLED 기본값을 1로 바꾼 것은 v0.3.5 §9의 명시적 요청입니다. 현재 프로젝트는 `sharekey_f429_OLED`이며 I2C1 PB8/PB9·`MX_I2C1_Init` 호출 비활성화를 유지해야 합니다. 기존 OLED 미설정 프로젝트에 코드만 덮어쓰면 HAL I2C 준비가 부족할 수 있습니다.
- OLED는 원본 RES의 A/D/H·사유·횟수를 표시할 뿐입니다. H 표시를 추가했다고 F 정책을 구현한 것은 아닙니다. 원본 메시지·판단·횟수 계산은 변경하지 않았습니다.
- v0.3.5 §9에는 OLED 실물 확인 항목과 '확인 안 한 것: OLED 실물 동작'이 동시에 남아 있습니다. 구체적인 1회 실물 보고를 기존 8줄 화면의 확인 근거로 사용하며 새 큰 글자의 실물 결과로 확대하지 않습니다.
- **마스터에 기재된 '발표자 곽동규'는 사용자 정정과 다릅니다. 곽동규는 발표자가 아닙니다.** 본 보고서와 README에 이를 명시했으며, 관리 중인 마스터 자체는 수정하지 않았습니다. PM이 역할 표와 발표 규칙을 정정해야 합니다.
- 요청서의 '11/5(수)'는 2026년 달력상 11/5(목)입니다. 날짜와 요일 중 어떤 것이 마감인지 팀 확인이 필요합니다. 새 일정을 임의 확정하지 않았습니다.

환경: Windows 노트북, MSVC `cl.exe` 파일 버전 19.51.36260.0, C11, `/W4`. 실제 `sharekey.c`·`sk_crypto.c`·`control.c`·`vehicle_app.c`·`oled.c`를 PC용 가상 I/O와 연결했습니다. UART·GPIO·타이머·I2C 하드웨어 시험은 아닙니다.

| OLED 픽셀 및 버스 | 원본 oled.c를 가짜 I2C에 연결, 페이지·열 주소로 프레임 복원 | 큰 화면 C/A·끝점, 기존 8줄, OLED OFF 총 5개 구성 통과 |
| OLED 화면 상태 | WAIT/ALLOW/DENY/HOLD, 숫자·INF, UNKNOWN/MOVING/EST/FAULT/NO HB | 출력 픽셀 검사 통과. ALLOW와 제어 실패를 별도 표시 |
| OLED 오류·복구 | 전송 실패 후 중지, 재초기화 및 화면 재전송 | 통과. 초기화 명령 바이트 불변 및 16바이트 분할 전송 확인 |
| 보드 빌드·실물 동작 | 이번 세션에서는 실행하지 않음 | 미검증. 실물 성공 또는 성능 목표 달성으로 쓰지 않음 |

컴파일 오류는 0건이나 **경고 0건은 아닙니다.** 여러 구성에서 중복 집계한 MSVC 경고는 31건입니다. 경고 위치는 변경하지 않은 `sharekey.c`의 C4244(정수 변환)·C4701(nv 초기화 가능성), `control.c` 및 기존 테스트 부분의 C4100(미사용 인수)입니다. 공유 코드를 임의 수정하지 않았고 로그를 보존했습니다. 보드 컴파일러 진단과는 별도로 팀 검토가 필요합니다. OLED 기본 A/C·8줄·OFF 시험 자체는 경고 0건, OLED 끝점 구성은 기존 control.c 경고 1건입니다.

추가 끝점 센서 구성의 첫 실행에서 명시적 stop 후 위치 센서가 UNLOCKED를 다시 확인하면 닫힘 에지에 구동이 재개되는 시험 실패를 발견했습니다. 자동 재잠금의 `armed` 조건을 추가했고 재잠금 단계의 12개 구성 모두 통과했습니다. 이후 OLED를 포함한 최종 17개 구성도 통과했습니다. 현재 장비 기본값은 ENDPOINTS=0입니다.

패키지의 기존 `ARM_BUILD_RESULTS.json` 및 10/28 검증 문서는 이전 버전의 기록입니다. 이번 수정본을 ARM GCC 또는 CubeIDE로 빌드한 기록으로 인용하지 않습니다. T01~T07 반복 측정 목표 달성을 주장하지 않습니다.

## 6. 막힌 것 / 질문

- v0.3.5 원문은 확인 완료. 채희 노트북의 현재 `sharekey_f429_OLED` 소스는 직접 확인하지 못해 변경 병합 전 대조 필요.
- UNKNOWN 상태의 문 닫힘 잠금 허용 여부는 팀 결정 필요. 이번 기본 동작에서는 제외.
- PF12 스위치 극성·디바운스 및 서보 1200/1800µs 방향·걸쇠 부하는 실물 확인 필요.
- 기존 8줄 OLED의 SSD1309 출력은 채희 보고서상 1회 확인. 새 큰 글자+재잠금 통합본의 CubeIDE 빌드·화면 가독성·I2C 타이밍·실제 구동은 미확인.
- 재부팅 후 키·횟수 저장은 여전히 미구현. RESET으로 상태를 보존할 수 없음.

## 7. 다음에 할 일

1. 동규: 갱신된 ZIP과 이 MD를 팀원에게 전달. 기백: 발표자 표기 및 마스터의 구현 상태 정정.
2. 채희: 현재 `sharekey_f429_OLED` 백업 후 네 파일 변경 병합(한 파일은 주석만), 기존 보정값 보존, CubeIDE 빌드·업로드.
