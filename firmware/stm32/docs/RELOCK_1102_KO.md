# 11월 2일 다시 잠그기 — 적용 및 실물 시험 순서

**곽동규는 발표자가 아닙니다.** 이번 작업은 STM32 제어 코드 구현·PC 시험·인계 문서 작성입니다. 발표 담당자는 별도 확인하며, 기존 마스터 §4·§15의 곽동규 발표자 표기는 정정 대상입니다.

기준: 추가로 받은 `00_master_design (2)(1).md` **v0.3.5** 및 `김채희_중간_OLED실물확인_1102.md`를 확인하고 갱신했습니다. 큰 글자 OLED를 포함한 적용 대상은 **`sharekey_f429_OLED`**입니다. 같은 이름의 이전 ZIP을 받은 경우 이번 갱신본을 다시 받으세요.

## 이번에 바뀐 동작

- 인증된 문열기 후 해제가 완료되고, 문 입력이 디바운스된 **열림 → 닫힘**으로 변하면 기존 `vehicle_app_request_lock()`을 호출합니다.
- `VC_RELOCK_ON_DOOR_CLOSE` 기본값은 1입니다. 0이면 기존 v2처럼 해제 상태를 유지합니다.
- 첫 안정 입력은 기준값으로만 사용합니다. 부팅 때 문이 닫혀 있어도 움직이지 않습니다.
- **UNKNOWN 위치에서 자동 잠금은 하지 않습니다.** 요청서에서도 의견을 구한 제안이므로 적용하지 않았습니다. 첫 시연은 인증된 문열기로 시작하세요.
- 제어가 활성화되어 있고(`armed`), 오류가 없으며 해제가 완료된 상태에서만 자동 잠금을 시도합니다. 정지 후에는 자동으로 다시 활성화하지 않습니다.
- 이동 중 발생한 닫힘은 예약하지 않습니다. 해제가 끝나고 문을 다시 열었다 닫아야 합니다. HB 복구나 오류 해제만으로 재시도하지 않습니다.
- 기존 HB·문 입력·모터 동작 안전 조건은 `control.c` 그대로입니다. 인증·횟수·통신 규칙을 변경하지 않았습니다.
- 정상 요청 로그: `# DOOR CLOSED -> LOCK ACT=OK`
- 끝점 센서 없는 기본 구성의 완료 로그: `# ACT DONE POSITION=LOCKED SOURCE=ESTIMATED`. 실제 위치 센서 측정 결과가 아닙니다.

## 1. 파일 전달 및 최신 기준 대조 — 동규 → 채희·기백

1. 이 ZIP과 `docs/01_gwak_relock_20261102.md`를 함께 전달합니다. 전달 자체는 사용자가 해야 합니다.
2. 기백에게 UNKNOWN 잠금 제안은 미적용 상태이며, 발표자 표기는 정정이 필요함을 전달합니다.
3. 채희가 실제 빌드 중인 **`sharekey_f429_OLED`**를 백업합니다. 이번 패키지는 다운받은 10월 28일 배포 v2를 기준으로 수정한 것으로, 채희 노트북의 현재 소스와 직접 비교하지 못했습니다.

## 2. 코드 적용 및 빌드 — 채희 노트북

**실제 보드 소스 변경은 아래 네 파일입니다. 기존 프로젝트 전체를 덮어쓰지 마세요.**

| 대상 | 적용 방법 |
|---|---|
| `Core/Src/vehicle_app.c` | 현재 파일과 `docs/RELOCK_1102.patch`를 비교합니다. 별도 수정이 없으면 새 파일로 교체하고, 차이가 있으면 해당 변경을 병합합니다. |
| `Core/Inc/config.h` | 아래 설정을 추가하고 `VC_ENABLE_OLED` 기본값을 1로 맞춥니다. 기존 서보 각도·다른 장치 설정을 보존합니다. |
| `Core/Src/oled.c` | 새 파일로 교체 또는 기존 변경과 병합합니다. 3배 글자, 4줄 화면이 추가됐습니다. |
| `Core/Inc/vehicle_platform.h` | 결과 표시 필드의 설명 주석만 갱신됐습니다. 구조체 배치나 API는 바뀌지 않았습니다. |

```c
#ifndef VC_RELOCK_ON_DOOR_CLOSE
#define VC_RELOCK_ON_DOOR_CLOSE 1
#endif
#if VC_RELOCK_ON_DOOR_CLOSE != 0 && VC_RELOCK_ON_DOOR_CLOSE != 1
#error "VC_RELOCK_ON_DOOR_CLOSE must be 0 or 1."
#endif
#ifndef VC_OLED_LARGE_TEXT
#define VC_OLED_LARGE_TEXT 1
#endif
```

RELOCK 설정은 `VC_ENABLE_SERVO` 다음, LARGE_TEXT 설정은 `VC_ENABLE_OLED` 다음에 있습니다. `sharekey.c/h`, `sk_crypto.c/h`, `control.c`, `board.c`, `port_stm32.c`는 교체할 필요가 없습니다. 패키지에는 재현용 전체 v2 소스가 포함되어 있습니다. `vehicle_app.c`에는 원본 RES 응답에서 표시용 결과·남은 횟수를 읽는 부분도 포함되므로 OLED 파일만 따로 적용하면 거부 시 남은 횟수 표시가 부정확할 수 있습니다.

빌드 조건:

- STM32CubeIDE 1.19.0 + STM32CubeF4 1.28.3, 실제 MCU F429ZI.
- C 시연: `APP_POLICY_MODE 'C'`, SERVO=1, MOTOR=0, ENDPOINTS=0, TEST_BUILD=0, RELOCK=1, OLED=1, LARGE_TEXT=1.
- 기존 PD14 TIM4_CH3 설정과 `MX_TIM4_Init` 호출 비활성화를 유지합니다.
- `sharekey_f429_OLED`의 I2C1 PB8/PB9 설정과 `MX_I2C1_Init` 호출 비활성화를 유지합니다. 이전 OLED 없는 프로젝트에 적용한다면 HAL I2C 드라이버와 모듈 설정이 먼저 필요합니다.
- Clean/Build 후 오류가 없음을 확인하고 대상 F429 프로젝트를 업로드합니다. 이 작업은 이번 PC 시험에 포함되지 않았습니다.

## 3. 문 스위치와 서보 준비 — 동규·민선

1. 전원을 끄고 배선합니다. AA 배터리를 먼저 끄고 USB 전원을 분리합니다.
2. 문 스위치의 접점을 PF12–GND에 연결합니다. 기본 설정은 내부 풀업·active-low이므로 **눌림=닫힘**입니다. 실제 모듈 단자와 접점 구성은 실물 표기로 확인합니다.
3. 문이 완전히 닫혔을 때 스위치가 눌리도록 설치합니다. 택트 스위치로 대신 시험하면 누른 상태를 유지합니다. 4핀 택트 스위치는 항상 이어진 같은 쪽 핀끼리 고르면 안 됩니다.
4. 기존 서보 배선을 확인합니다: 신호 PD14(CN7 D10), 전원 AA 4개 홀더, AA 음극과 Nucleo GND 공통. 서보 전원은 Nucleo 5V에서 가져오지 않습니다.
5. 최초 시험은 걸쇠에 부하를 주지 않는 상태로 합니다. 1200µs=잠금, 1800µs=해제 방향과 기구 간섭을 확인한 뒤 문짝에 결합합니다. 전원이 들어간 서보를 손으로 억지로 돌리지 않습니다.

## 4. 한 번 열고 닫기 — 먼저 이것만 확인

1. USB 전원을 먼저 연결하고 기존 Pi 중계 프로그램을 실행해 HB가 유지되게 합니다. 그다음 서보 AA 전원을 켭니다. 부팅만으로 서보가 움직이지 않아야 합니다.
2. 서버·앱·Pi의 IP는 그날 확인한 주소를 사용합니다. 예전 `172.20.10.11/12`가 그대로라고 가정하지 않습니다.
3. 기존 앱 절차로 테스트 키를 발급·등록하고 인증된 문열기를 한 번 보냅니다. `AUTH ALLOW ... ACT=OK` 및 `ACT DONE POSITION=UNLOCKED`를 기다립니다.
4. 스위치를 놓아 문 열림을 만들고, 다시 눌러 닫힘을 만듭니다. 각 상태를 약 1초 유지하면 30ms 디바운스보다 충분히 깁니다.
5. 스위치를 계속 누른 상태에서 `DOOR CLOSED -> LOCK ACT=OK`와 `ACT DONE POSITION=LOCKED SOURCE=ESTIMATED`를 확인합니다. 서보가 실제 잠금 방향으로 움직이는지도 확인합니다.
6. 계속 누르고 있을 때 잠금 요청이 반복되지 않아야 합니다. 다음 문열기 전에 닫힌 상태를 유지합니다.

잠금 이동 중 스위치를 놓으면 기존 보호 동작으로 `FAULT_DOOR`가 발생하고 구동이 차단됩니다. 실제 로그 표기는 `CONTROL FAULT=DOOR_OPEN`입니다. HB가 2초 끊기면 `CONTROL FAULT=LINK_TIMEOUT`입니다. 원인을 해결하고, 필요하면 AA 전원을 끈 상태에서 HB를 유지하며 보드를 RESET한 뒤 다시 등록부터 진행합니다. **RESET은 RAM의 키·횟수·동기화 상태를 지웁니다. 보존 기능이 아닙니다.**

## 5. C 정책과 실물 반복 확인

1. 앞의 단일 동작이 성공한 뒤 기존 데모 시나리오로 진행합니다. 인증된 동기화로 한도가 복구된 상태에서 서버↔차량만 끊고 서버에서 취소합니다. 앱↔Pi 및 Pi↔STM32/HB는 유지합니다.
2. 문열기 → 해제 완료 → 문 열기 → 문 닫기 → 잠금 완료를 매번 확인하며 6회 시도합니다.
3. 기대 동작은 C에서 1~4회 허용, 5~6회 사유 05 거부·잠금 유지입니다. 아직 이번 코드로 실제 보드에서 측정한 결과가 아닙니다.
4. 서버 연결을 복구해 인증된 취소 동기화가 반영되면 사유 03으로 거부되는지 확인합니다.
5. A 재촬영이나 발표 리허설은 팀의 해당 담당자가 진행합니다. **곽동규에게 발표자 업무를 배정한 문서가 아닙니다.**

## 문제가 있으면

- 문을 계속 닫고 있었음: 새 열림→닫힘이 없어 동작하지 않는 것이 정상입니다.
- `UNKNOWN`: 먼저 인증된 문열기와 해제 완료가 필요합니다.
- 해제 이동 중 문을 닫았음: 해제 완료 후 다시 열었다 닫습니다. 자동 예약은 하지 않습니다.
- 오류 발생: 직전 로그, 설정값, 실제 움직임을 함께 기록합니다. 횟수 차감은 실행 실패여도 취소되지 않습니다.
- 되돌리기: `VC_RELOCK_ON_DOOR_CLOSE 0`으로 빌드하면 기존 v2의 자동 재잠금 없는 동작입니다.

## OLED 큰 글자 화면 및 검증 범위

채희 보고서에 따르면 기존 8줄 화면을 JMD2.42 IIC 128×64 SSD1309에서 1회 확인했습니다. 이 사실을 근거로 기존 초기화 바이트·주소 0x3C·페이지 전송 방식을 그대로 유지하고, 기존 3×5 글자를 가로·세로 3배(9×15픽셀)로 확대했습니다. **이번 큰 글자 수정본을 실물 확인한 것은 아닙니다.**

| 줄 | 표시 |
|---|---|
| 1 | 비교 방식 `C` 또는 `A`; 제어 오류 시 `C FAULT` 등 |
| 2 | `WAIT`, `ALLOW`, `DENY 05` 등; H 결과는 `HOLD 07`로 표시 가능(새 정책을 구현한 뜻 아님) |
| 3 | `LEFT 3`, `LEFT 0`, 제한 없음은 `LEFT INF`, 초기값은 `LEFT --` |
| 4 | `LOCK EST` / `UNLOCK EST`, 이동 중 `MOVING`, 위치 불명 `UNKNOWN`; 오류 또는 구동 실패 시 `LINK LOST`, `NO HB`, `ACT BUSY` 등 |

`ALLOW`는 인증 허용이며 실제 서보 성공을 뜻하지 않습니다. `EST`는 끝점 센서 없이 시간으로 추정한 위치입니다. 남은 횟수는 판단 코드가 전송하는 RES를 그대로 표시하며, 표시 코드가 판단이나 구동을 결정하지 않습니다.

OLED 배선은 보고서대로 GND→GND, VCC→3V3, SCL→PB8(D15), SDA→PB9(D14), RES 미연결입니다. 새 빌드에서 먼저 WAIT 화면을 확인하고 open·tamper·횟수 소진 시 표시를 점검하세요. 기존 화면으로 되돌릴 때는 `VC_OLED_LARGE_TEXT=0`, OLED 전체를 끌 때는 `VC_ENABLE_OLED=0`입니다.

PC 호스트 C 시험은 **17개 실행 구성**에서 통과했습니다. 실제 빌드 로그와 실행 결과는 `docs/host_1102/`에 있습니다. OLED 시험은 가짜 I2C가 받은 바이트·화면 픽셀·전송 오류 복구를 확인한 것으로 전기적 타이밍·실물 화면 검증이 아닙니다. `docs/oled_preview_1102.png`는 PC 시험의 화면 데이터로 만든 미리보기이며 실물 사진이 아닙니다. 이전 `ARM_BUILD_RESULTS.json`, `HOST_TEST_RESULTS.json` 등은 10월 28일 원본의 기록이며 이번 수정본의 ARM 빌드 결과가 아닙니다.
