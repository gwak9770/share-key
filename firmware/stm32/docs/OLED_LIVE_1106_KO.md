# 곽동규 작업 정리 — OLED 상태 갱신 수정

> 날짜: 2026-11-06 / 설계 기준: 00_master_design (5).md v0.3.11
> 코드 기준: stm32_vehicle_control_f429_v2_1103_R1수정_1104.zip

## 1. 한 일
- OLED가 마지막 KEY/RES 응답에 머물던 문제를 수정했다. 인증된 서버 동기화 후 현재 표시 대상 KID의 내부 상태를 조회한다.
- 온라인 사용 후 LEFT 3 → 4 복구, 키 취소 후 문 열기 재요청 없이 DENY 03 / LEFT 0 표시를 추가했다.
- 500ms 표시 호출 제한을 제거했다. 변한 화면만 전송하며, 전송 중에는 현재 프레임을 끝낸 다음 최신 상태를 그린다.

## 2. 표시 규칙
| 상황 | 표시 |
|---|---|
| C 정상 사용 | ALLOW / LEFT 3 등 실제 남은 횟수 |
| 해당 키의 인증된 동기화로 횟수 복구 | LEFT 4, 이전 ALLOW 또는 진단 결과 유지 |
| 기존 DENY 05에서 횟수 복구 | WAIT / LEFT 4 (새 인증 허용으로 오해하지 않도록 ALLOW를 만들지 않음) |
| 해당 키 취소 동기화 수신 | DENY 03 / LEFT 0 |
| 인증된 반납 완료 | DENY 09 / LEFT 0 (반납 성공 후 키 사용 불가 상태) |
| A 정상 키 | LEFT INF |
| 키 등록 | 기존 KEY OK / KEY 번호 표시 유지. 취소된 키 재등록 시 DENY 03 / LEFT 0 |
| 변조·재전송 등 요청 거부 | 해당 요청의 사유 01/02 등을 표시. 다음 정상 동기화에서는 현재 취소 상태를 다시 표시 |

LEFT 0은 취소·반납된 키의 **실제로 사용 가능한 횟수**다. 판단 모듈 내부 원시 카운터와 통신 RES의 LEFT는 기존 값을 유지하므로, 로그/웹의 원시 잔여값과 OLED의 유효 잔여값은 다를 수 있다. 키가 여러 개이면 마지막 KEYOK/KEYNG/RES에 나온 키를 표시한다. KEYNG는 등록 실패 진단을 유지한다.

## 3. 변경 파일과 적용
먼저 김채희 노트북의 실제 CubeIDE 프로젝트를 통째로 백업한다. ZIP의 `apply/Core`에서 다음 6개 파일만 같은 위치에 덮어쓴다.

| 폴더 | 파일 |
|---|---|
| Core/Inc | sharekey.h, vehicle_platform.h |
| Core/Src | sharekey.c, vehicle_app.c, port_stm32.c, oled.c |

`sharekey.c`와 `sharekey.h`는 반드시 함께 적용한다. `config.h`는 덮어쓰지 않는다. VC_DEMO_MODE_SELECT 등 현재 설정을 유지한다.

Clean → Build → 오류 0 확인 → Run As/업로드 → 보드 RESET → 새 KID로 등록한다. 서버/중계를 재시작했어도 RESET과 재등록을 한다.

이번 수정은 R1 기준이다. 별도 OLED수정_1104.zip(버스 복구·DOOR CL/OP)을 적용한 프로젝트라면 6개 전체를 덮어쓰지 말고 `OLED_LIVE_1106.patch` 변경분을 병합해야 기존 수정이 유지된다. 해당 수정본 실파일은 확보하지 못해 이번 묶음에 포함하지 않았다.

## 4. 설계와 공유 코드 관련
- HMAC, nonce 검증, 판단 순서, 횟수 차감/복구, 취소/반납 처리, 메시지 형식, 핀, 서보 제어는 바꾸지 않았다.
- sharekey.c/h에 읽기 전용 `sk_get_key_view()`만 추가했다. 별도 가상 카운터나 수신 SYNC 문자열 추측으로 화면을 갱신하지 않는다.
- 추가 조회 함수를 제거하면 sharekey.c가 기준본과 동일함을 자동 비교했다. sk_crypto.c/h와 control.c는 동일하다.
- 전체 공유 저장소의 stm32/sharekey.c/h도 동일한 조회 API를 반영해야 한다. 이 PC에 없는 팀 공유 저장소는 수정하지 않았다. Python 판단에는 변경이 없다.
- 동기화 주기 2초는 유지한다. 서버 클릭 즉시 전파되는 push 방식은 아니다. 정상 통신에서는 다음 인증 동기화 수신 후 표시하며, 실제 화면 반영 지연은 실물 측정 전이다.
- 오프라인에서는 취소 사실을 아직 알 수 없으므로 이전 상태/잔여 횟수를 유지하는 것이 정상이다.
- 전송은 기존 16바이트 청크 단위다. 같은 픽셀은 재전송하지 않는다. 비교용 RAM 1024바이트와 유효성 플래그를 추가했다.

## 5. 검증 결과
- MSVC /W4 호스트 시험: 19/19 구성 통과. 기존 코드의 경고는 남아 있으며 경고 0으로 주장하지 않는다.
- 추가 시험: 실제 서명 KEY/REQ/RESP/SYNC를 사용해 3→4 복구, 재요청 없는 취소 표시, 변조/재전송 동기화 거부, 다중 KID 선택, 05 해소, 반납 표시, 원시 카운터/RES 보존 확인.
- OLED 가상 I2C: LEFT 4, DENY 03, LEFT 0 픽셀, 동일 화면 100회 호출 시 전송 없음, 전송 중 프레임 보존, 오류 후 재초기화 확인.
- 이번 수정본의 ARM 빌드·CubeIDE 빌드·실물 OLED 시험은 미수행(현재 PC에 ARM 도구/CubeF4 없음). 과거 패키지의 ARM 결과는 이번 검증 결과가 아니다.

## 6. 실물 확인 순서
1. 정상 키 등록 → KEY OK 확인.
2. 온라인 문 열기 → LEFT 3 → 다음 인증 동기화 후 LEFT 4 확인. 추가 문 열기 클릭 없이 확인한다.
3. 온라인 공유 키 취소 → 다음 동기화 후 DENY 03 / LEFT 0 확인. 이때 서보가 추가로 움직이지 않는지 확인한다.
4. 취소 키 문 열기 → 계속 거부/LEFT 0.
5. 새 KID 등록 후 오프라인 C → 해제·재잠금 4회, 5·6번째 DENY 05/LEFT 0 확인.
6. 취소하지 않은 새 키로 05 소진 뒤 온라인 복귀 → WAIT/LEFT 4 확인. 취소한 키는 DENY 03/LEFT 0이어야 한다.
7. 다시 잠그기 10회 반복과 OLED 갱신을 함께 확인한다. 스위치는 해제 후 떼고 다시 눌러 열림→닫힘을 만들며 잠금 완료까지 약 0.5초 이상 누른다.

작성자는 곽동규이며 발표 담당자를 지정한 문서가 아니다.
