# 곽동규 작업 정리 — 서보 이동 범위 약 90도 보정

> 날짜: 2026-11-06
> 기준: stm32_vehicle_control_f429_v2_1103_LIVE문상태_1106.zip

## 1. 한 일
- 사용자가 현재 약 45도 움직인다고 보고한 서보의 이동 범위를 약 90도 목표로 넓혔다.
- 중심 1500μs를 유지하고 잠금/해제 PWM 펄스 차이를 600μs에서 1200μs로 두 배 늘렸다.
- 실제 각도는 미측정이며 보드 업로드 전 PC 검증만 수행한다.

## 2. 변경 값
| 항목 | 이전 | 수정 |
|---|---:|---:|
| SERVO_LOCK_US | 1200u | 900u |
| SERVO_UNLOCK_US | 1800u | 2100u |
| PWM 주파수 | 50Hz | 50Hz 유지 |
| 센서 없는 이동 추정 시간 | 500ms | 500ms 유지 |

45도 관찰값과 펄스 차이가 비례한다고 가정한 초기 보정값이다. 정확한 90도를 보장하지 않으며, 이전 팀 문서의 1000/2000μs 제안과 다르다. 1000/2000은 차이가 1000μs라 기존 600μs의 두 배가 아니므로 이번에는 900/2100을 사용했다.

## 3. 적용 방법
현재 CubeIDE 프로젝트의 Core/Inc/config.h를 백업하고 **아래 두 줄만 수정하는 방법을 권장한다.** 로컬 USER 전환·서보 극성 등 다른 설정은 유지한다.

```c
#define SERVO_LOCK_US 900u
#define SERVO_UNLOCK_US 2100u
```

ZIP의 apply/Core/Inc/config.h는 최신 LIVE문상태 배포본 기준의 전체 참고 파일이다. 로컬 설정을 따로 바꾼 적이 없다면 덮어쓸 수 있다. 변경 패치 servo_90_1106.patch도 포함한다.

Clean → Build(오류 0 확인) → Run As/업로드 → 보드 RESET → 키 재등록.

## 4. 실물 확인
1. 처음에는 걸쇠의 부하를 풀어 서보 날개가 양쪽 위치까지 움직일 공간을 확보한다.
2. Pi 중계의 HB를 유지하고 정상 키로 문 열기를 요청해 해제 각도를 확인한다.
3. 해제 완료 후 스위치를 떼었다 다시 누르고, 잠금 이동 완료까지 누른 채 유지한다.
4. 두 위치 사이 각도를 확인하고 걸쇠에 연결해 잠금·해제 여부를 확인한다. 부품에 걸리거나 계속 떨면 서보 전원을 끄고 범위를 줄인다.
5. 약 90도가 아니면 실제 각도를 기록해 추가 보정한다. 500ms는 도착 추정일 뿐이므로 도착 전 출력 종료가 의심되면 로그와 동작을 보고 이동 시간을 별도로 검토한다.

부팅 때 자동 이동하지 않으며 잠금은 문 열림→닫힘 변화로 수행한다. 키 인증·횟수·OLED LIVE·문 상태 로그·I2C 복구 코드는 이번에 수정하지 않았다. 공유 설계 문서는 직접 변경하지 않았으며 실물 보정 결과를 팀장에게 전달해 반영한다.

## 5. 검증 결과
- 변경된 설정으로 MSVC /W4 호스트 시험 19/19 구성 통과(실제 제어·인증·재잠금·OLED 코드, 가상 입출력). 기존 경고는 남아 있다.
- 이번 수정본의 ARM/CubeIDE 빌드 및 실물 90도 동작은 미확인이다.
