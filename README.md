# 차량 공유 디지털키 오프라인 사용 제한 모듈

졸업 프로젝트의 코드·설계·시험 기록을 함께 관리하는 협업 저장소입니다.
2026-11-06 초기 기준에 2026-11-07 최신 로컬 LIVE문상태판과 서보 보정본을 반영했습니다. 팀 전체 최신 통합본이나 실물 배포 완료본으로 확정한 것은 아닙니다.

## 포함된 자료

- `firmware/stm32/`: STM32F429 제어·재잠금·OLED 갱신 코드, 기존 시험과 적용 문서. 11/6 작업 사본에서 바이트 그대로 복사했습니다.
- `docs/history/`: Pi 시험과 팀 전달·검토 MD 문서 원문 사본.
- `docs/IMPORT_MANIFEST.json`: 파일별 출처와 SHA-256.
- `CONTRIBUTING.md`: 브랜치·PR 협업 절차.

서버·웹·Pi 실행 코드와 팀 최신 설계 원문은 이번에 접근 가능한 파일에서 찾지 못했습니다. 담당자가 확인한 사본을 별도 PR로 추가해야 합니다. `sources/`와 기존 작업 폴더는 이동하거나 수정하지 않았습니다.

## 최근 반영

- LIVE문상태판의 I2C 버스 복구·OLED DOOR CL/OP 표시·디바운스된 문 상태 로그와 관련 회귀 시험을 반영했습니다. 해당 병합·문 상태 로그는 팀원 기여이며 곽동규의 단독 작업으로 기록하지 않습니다.
- 곽동규 작업의 서보 900/2100μs 보정값을 반영했습니다. 약 90도 목표 시험값이며 실물 각도는 미확인입니다.
- [업로드 범위·검증·제외 항목](docs/UPLOAD_20261107.md), [서보 적용 안내](firmware/stm32/docs/SERVO_90_1106_KO.md)를 확인하세요.
- `docs/IMPORT_MANIFEST.json`과 기존 시험 JSON은 초기 반입 당시 기록입니다. 이번 변경의 출처·해시는 `docs/UPLOAD_MANIFEST_20261107.json`을 기준으로 합니다.

## 먼저 읽기

11/6 동작과 한계는 [OLED 변경 기록](firmware/stm32/docs/OLED_LIVE_1106_KO.md)을 우선합니다. 이전 README·검증 JSON·패키지 매니페스트는 당시 기록이며 이번 Git 도입의 빌드 성공을 뜻하지 않습니다. 실제 CubeIDE 프로젝트에 반영하기 전 기존 파일을 백업하고, 보드 설정과 적용 이력을 대조하세요.

기존 호스트 시험은 아래처럼 실행합니다. Python과 GCC/Clang 또는 MSVC 개발 환경이 필요합니다.

```sh
cd firmware/stm32
python tools/run_host_tests.py --cc gcc
python tools/run_oled_tests.py --cc gcc
```

MSVC 개발자 터미널에서는 `--cc cl`을 사용합니다. 보드 빌드·실물 시험은 별도입니다.

## 비밀정보와 설정

실제 차량 키, 토큰, 발급 키 JSON, 서버 상태, 인증서, `.env`, 로그, 빌드 결과는 커밋하지 않습니다. `.gitignore`는 이미 추적 중인 파일이나 소스 내부의 비밀정보를 제거하지 않으므로 PR 전 내용을 확인하세요.
원본 `sharekey.c`에는 주석으로 명시된 순차 바이트 데모 마스터키가 있습니다. 원문 보존을 위해 유지했으며 실제 차량용 비밀키가 아닙니다. 실제 운용 전 펌웨어·서버 양쪽의 별도 비밀키 주입 방식을 설계해야 합니다.

## 저장소 상태

공유 저장소는 [gwak9770/share-key](https://github.com/gwak9770/share-key)이며 비공개입니다. 기본 브랜치는 `main`이고 최초 커밋 `b445034`의 업로드를 확인했습니다. 이 로컬 폴더 이름은 `sharekey-offline-limit`이지만 GitHub 저장소 이름은 생성 화면에 사용자가 입력한 `share-key`를 사용했습니다.
팀원 초대와 브랜치 보호 규칙은 아직 설정하지 않았습니다. [협업 안내](CONTRIBUTING.md)에 따라 팀원 계정과 검토 절차를 정한 뒤 적용하세요.
